# 런킵 설계

## 확정된 제품 방향

한국의 공원·하천변·도로에서 휴대폰으로 러닝을 기록하는 Kotlin Android 앱이다. 운동 데이터는 앱 내부 SQLite에 저장한다. 카카오 지도에는 네이티브앱 키를 사용한다. 백엔드와 다른 플랫폼 구현은 후속 범위다.

핵심 차별점은 직접 찍은 좌표 코스를 따라 달리기와 구간별 목표 페이스 안내다. 기본 러닝 앱의 거리·시간·페이스·지도·구간 통계를 함께 제공하되 Nike Run Club/Samsung Health 전체 기능과의 동등성을 주장하지 않는다.

## 측정과 기록

`RunService`가 하나의 이벤트 채널로 시작/일시정지/재개/종료, GPS, 1초 타이머를 순서대로 처리한다. 위치와 스냅샷은 Room 트랜잭션으로 저장한다. GPS 지점마다 저장하고 위치가 없는 동안에도 5초마다 요약을 저장한다. 화면은 서비스의 `StateFlow`를 구독하며 측정 주체가 아니다.

- active time: RUNNING 상태의 monotonic clock 누적. wall clock은 심박수 정렬과 GPX 타임스탬프에만 사용.
- 거리: 유효 GPS 지점 사이의 WGS84 좌표 Haversine 거리 누적.
- 정확도 25m 초과, 단시간 12m/s 초과 위치 튐 제외. 15초 넘는 위치 공백과 일시정지는 새 segment로 분리하고 직선 거리를 추가하지 않음.
- 20초 동안의 누적 거리/시간으로 현재 페이스 계산. 최소 8초·8m가 없으면 값 대신 대시 표시.
- 케이던스: 휴대폰 TYPE_STEP_DETECTOR의 최근 20초 이벤트. 최소 6걸음. 전용 워치 측정값과 같은 정확도를 전제하지 않음.
- 자동 일시정지: 정확도 15m 이하·수신 나이와 연속 위치 간격 3초 이하인 GPS로 정지가 8초 지속될 때. 속도가 있으면 0.5m/s 이하, 없으면 고정 기준 위치 주변의 오차 범위 내 정지를 확인한다. 신호 소실·정확도 악화는 정지 확인을 초기화한다.
- 자동 재개: 자동 정지 상태에서 3개 이상 연속 이동 구간·2초 이상을 확인한다. 속도가 있으면 1.2m/s 이상과 좌표 진행 0.5m/s 이상, 없으면 좌표 진행 1m/s 이상을 요구한다. 순이동은 `max(4m, 시작/현재 정확도의 평균)` 이상이고 전체 이동 길이의 75% 이상이어야 한다. 단일 속도/좌표 튐, 왕복 흔들림, 정확도 급격한 악화, GPS 공백/만료는 확인 근거를 초기화한다.
- 재개 확인 중 시간·거리·트랙 지점은 누적하지 않는다. 확인된 위치가 새 segment의 시작점이며 정지 구간과 직선으로 연결하지 않는다. 수신 지연으로 재개 시계가 뒤로 가지 않도록 실제 처리 시각에서 시간을 재개한다. 수동 정지는 자동 재개하지 않으며 자동 정지 중 수동 정지 요청도 PAUSED로 전환한다.
- 개발용 `RunEngine.autoPauseDiagnostics`는 판단 사유, 연속 이동 구간 수, 확인 시간, 순이동과 요구 거리를 제공한다. `lastAutoPauseTransition`에 직전 자동 정지/재개 근거를 유지한다. 좌표·개인정보를 포함하거나 DB에 저장하지 않는다.
- 정상 종료 전까지 전체 저장. 시스템 종료로 복구된 운동은 INTERRUPTED로 시작하며 복구 대기 시간은 제외. 사용자가 직접 재개/종료.

GPS 수신 품질, 폰 휴대 위치, GPS 속도 제공 여부와 배터리 정책에 따른 현장 튜닝은 필요하다. 화면 꺼짐 중 기록을 위해 foreground location service와 partial wake lock을 사용한다. 서비스가 끝나면 해제한다. 항상 위치 권한은 요청하지 않는다.

위치 공급은 `LocationController`에서 Google Play Fused Location 고정밀 요청으로 통합한다. 지도·진단 화면·운동 서비스가 각각 구독을 소유하며 마지막 구독이 끝날 때 해제한다. 지도와 진단 화면은 화면 생명주기에 맞춰 구독하고 서비스는 운동 종료까지 유지한다. GPS만 강제하는 대신 통합 위치로 첫 위치를 표시하되, 오차 25m 초과 위치는 기존 운동 필터에서 계속 제외한다. 시작/재개 이전의 캐시 위치는 거리로 더하지 않는다. 위치 꺼짐, 정확한 권한 미허용, 첫 수신, 갱신 지연, 정확도 부족을 각각 표시한다.

음성은 서비스와 테스트 화면에서 `SpeechPlayer`를 사용한다. 화면의 `paceText()`는 콜론 표시를 유지하고 음성은 `paceSpeechText(초/km)`의 명시적 분·초 단위를 사용한다. `durationSpeechText(밀리초)`는 경과 시간을 시간·분·초로 표현한다. 시각을 나타내는 [TtsSpan.TimeBuilder](https://developer.android.com/reference/android/text/style/TtsSpan.TimeBuilder)를 페이스에 적용하지 않는다.

`Announcement`는 종류, 단조시각 발생 시간, 우선순위와 타입별 값(초/km, km, 구간 이름)을 갖고 `speechText()`가 문장을 만든다. 평균·현재·목표 페이스는 별개 종류/필드로 유지한다. 회전 문장은 기존 코스 탐색기에서 생성하고 이벤트에 담는다. 서비스는 `AnnouncementQueue.next(now, status)`로 선택하고 TTS가 요청을 수락한 뒤 `acknowledge(event)`로 해당 이벤트만 제거한다. 음성이 꺼져 있으면 화면 안내 후 제거한다. 준비 중이거나 오디오 포커스를 얻지 못하면 다음 1초 서비스 틱에 재시도한다.

상태 안내, 회전 안내, 구간·목표·1km 안내, 샘플 페이스 순서로 선택하며 같은 우선순위는 발생 순서를 유지한다. 기다리는 동안 현재/목표/초과 페이스, 상태, 구간 안내는 종류별 최신값을 남긴다. 샘플 페이스와 회전은 15초가 지나면 폐기하고 정지 상태에서는 제거한다. 구간·목표·1km 이정표는 다른 안내와 겹쳐도 삭제하지 않는다. 재생 중 안내를 강제로 끊지는 않으며 긴 문장 중 회전 안내 지연은 기기에서 확인할 후속 튜닝 대상이다. 페이스 경고 재안내는 실제 발화 시작 기준 10~120초이며 기본 30초다.

`SpeechPlayer.playback`은 준비/대기/재생/오류/중지/종료 상태를 공유한다. 요청 시점부터 재생 중으로 표시하여 TTS 준비 구간의 중복 요청을 막고, [UtteranceProgressListener](https://developer.android.com/reference/android/speech/tts/UtteranceProgressListener)의 시작·완료·오류·중지 콜백은 메인 스레드에서 현재 발화 ID에만 적용한다. 재생 완료 후 다음 틱에 후속 안내를 선택한다. 음량·속도·높낮이는 기존 설정 JSON에 기본값을 갖는 필드로 추가하며 DB 마이그레이션은 필요 없다. 운동 중에는 경보와 공유하는 오디오 포커스를 발화 동안 사용하고 완료 시 음성 몫만 반환한다. 진단 화면은 자체 포커스를 사용한다. 진단 화면은 운동을 만들지 않는다.

## 모바일 공통 기반

드로워·표준/모달 시트·창 크기·접근성·거리/운동 시간/페이스 입력 정책과 후속 UI용 API는 [모바일 공통 UI 규칙](MOBILE_UI.md)에 정리한다. 기존 Compose Material 3를 사용하고 입력은 적용 전까지 초안으로 분리한다.

## 목표와 페이스 구간

코스 지점별 목표와 세 설정 흐름은 [코스·페이스 통합 정책](COURSE_PACE_INTEGRATION.md)을 따른다. 좌표 배열을 보존하며 지점 ID·방향 있는 인접 연결·운동 진행 스냅샷을 추가한다. 교환 JSON은 v2로 내보내고 v1/v2를 읽으며 기존 Room JSON은 기본값으로 호환한다.

구간의 amount는 DISTANCE일 때 m, TIME일 때 s. 목표 페이스는 s/km 정수다. 예를 들어 1km 7:00 + 2km 6:25의 목표 평균은 `(420 + 2×385) / 3 = 396.67 s/km`로 약 6:37이다.

DISTANCE는 실제 누적 거리로, TIME은 운동 시간으로 전환한다. 거리 경계의 시간은 경계를 통과한 두 지점 사이에서 보간한다. 시간 경계의 거리는 전환 시점에 알려진 위치를 기준으로 하므로 GPS 업데이트 단위의 오차가 있다. 구간을 반복하면 동일 구간 목록을 펼쳐서 저장한다. 완료 시 알림 중단이 기본이고 설정을 끄면 마지막 목표 페이스를 계속 안내한다.

거리 구간만 있는 계획은 합계를 목표 거리로 설정한다. 시간 구간이 포함된 계획의 거리는 예상값이므로 자동으로 목표 거리로 고정하지 않는다. 목표 거리가 없는 무계획 달리기도 지원한다.

목표를 달성해도 자동 종료하거나 원본을 잘라 저장하지 않는다. `goalMeters`, `goalActiveMs`, `goalEpochMs`에 도달 경계를 저장한다. 결과 화면 기본값은 목표까지이며 “목표까지/전체 기록” 선택으로 통계·지도·구간·그래프·심박수 범위를 전환한다. 전체 표시는 원본의 목표 경계를 해제한 표시용 사본으로 계산하고 저장 원본은 유지한다. 목표 미달 운동은 전체를 표시한다.

## 코스와 회전

코스 편집은 전체 화면 지도와 하단 지점 드로어로 구성한다. 저장 코스는 패널을 제외한 지도에 전체 경로를 한 번 맞추고, 새 코스는 최초 수신 위치에서 연다. 빈 곳 터치로 추가, 마커 짧은 터치로 선택, 선택된 마커 길게 누른 후 드래그로 이동한다. 드로어에서 선택·삭제하거나 선택 지점 뒤로 새 점을 삽입할 수 있다. 마커 위는 코스 거리 값, 선 가운데는 연결 구간 거리다. 첫 지점의 0km와 반복 사용법은 표시하지 않는다. 한 번 실행 취소와 저장 전 변경 확인을 제공한다. 200개를 넘는 가져온 코스는 지도 라벨을 시작/끝/선택 지점으로 줄이고 목록에서 모든 지점을 선택한다.

지도는 native touch를 우선 처리하고 상위 세로 스크롤의 가로채기를 막는다. 48dp 아이콘 ‘현재 위치로’는 유효 GPS 위치로 이동, ‘코스 전체 보기’는 계획/기록 전체를 화면에 맞춘다. 위치/경로가 없거나 preview에서 지원하지 않는 조작은 비활성이다. 달리기 중에는 기본적으로 위치를 따라가며 사용자가 지도를 움직이면 해제한다. 실제 현재 위치 점을 유지하며 별도 ‘내 위치’ 범례는 표시하지 않는다.

코스는 **순서 있는 좌표 목록**이다. 점 사이는 직선이며 실제 길의 통행 가능 여부를 알지 못한다. 사용자가 굽은 산책로를 따라 점을 충분히 찍어야 한다. 지도 SDK는 배경 표시/카메라/지도 클릭/선 그리기를 담당하고 자동 길찾기 API는 호출하지 않는다.

연속된 세 지점의 방위각 차이로 방향을 계산한다. 인접 선분이 각 8m 이상이고 변화각 35도 이상인 지점을 안내 후보로 사용한다. 기본 선행 거리 20m, 설정 범위 10~100m. 원래 코스 위의 진행거리 기준이며 단순 직선 근접 알림이 아니다. 루프 교차점에서 뒤쪽 구간으로 건너뛰지 않도록 직전 진행거리와 실제 이동량으로 후보 구간을 제한한다.

35m 넘게 이탈하면 최대 60초에 한 번 알림만 준다. 사용자가 의도적으로 이탈할 수 있으므로 강제로 경로를 바꾸지 않는다. 크게 지름길로 건너간 뒤 코스 후반에 합류하면 진행거리 제한 때문에 안내가 자동 복구되지 않을 수 있다. 복잡한 루프·왕복·중간 합류는 현장 검증 및 후속 알고리즘 개선 대상이다.

## 구간별 진행 표

지도 아래에서 1km 단위 또는 코스 지점별 표를 선택한다. 완료·진행 중·대기·미완료와 해당 구간 평균 페이스를 표시한다. 기록 상세의 목표/전체 전환에도 같은 범위를 적용한다.

지점별 계산은 두 선택지를 제공하며 사용자가 기준을 선택하기 전에는 계산하지 않는다. ‘누적 거리 기준’은 코스 각 선분의 길이를 실제 운동의 누적 거리에 대응시킨다. ‘지점 통과 기준’은 GPS 정확도를 고려한 8~20m 범위에서 지점을 순서대로 통과한 시간/거리로 나눈다. GPS 공백·일시정지 선분을 연결하지 않고 뒤쪽 교차점으로 순서를 건너뛰지 않는다. 지점을 건너뛴 경우 후속 지점까지 자동 완료하지 않는다. 선택 전에는 지점별 결과를 계산하지 않는다.

## 심박수

초기 데이터 흐름:

```text
Galaxy Fit3 → Samsung Health → Health Connect
                                  ↓ 명시적 읽기 권한 + 사용자의 가져오기
휴대폰 GPS → Runkeep RunService → SQLite ← 타임스탬프로 정렬한 심박수
```

Health Connect에 Samsung Health가 실제로 기록한 심박수만 읽는다. 권한은 READ_HEART_RATE, READ_EXERCISE이며 쓰기 권한은 없다. 운동 시작/종료가 겹치는 Samsung Health 세션을 제시하고 사용자가 선택한 시간 교집합을 가져온다. 세션이 없을 때 런킵 시간 범위로 가져오기는 별도의 선택이다. 모든 결과는 페이지 끝까지 읽는다. 빈 구간을 보간해 심박수를 만들어내지 않는다.

> 미래 실시간 연결: Wear OS 앱 + Health Services/데이터 전송, 또는 표준 Heart Rate Service를 제공하는 BLE 센서용 어댑터를 추가한다. Fit3가 일반 BLE 심박수 센서로 공개된다고 가정하지 않는다. Health Connect 폴링을 실시간으로 취급하지 않는다.

## 저장 형식

Room이 관리하는 앱 전용 `runkeep.db`, schema version 1. 스키마 변경 시 마이그레이션을 작성하며 destructive migration은 사용하지 않는다.

| 테이블 | 키 | 내용 |
| --- | --- | --- |
| courses | id | 이름, version, 순서 있는 좌표의 JSON |
| plans | id | 이름, 구간 목록의 JSON |
| runs | id | 시작/종료/상태/목표 도달 지표, 당시 코스·계획의 사본 JSON |
| track_points | runId + sequence | 좌표, epochMs, activeMs, 누적 m, 정확도, 고도, segment, 케이던스 |
| heart_samples | runId + sourceId + epochMs | bpm, 원본 Health Connect record id |

SQLite 안에서는 레코드 단위로 저장하며 GPX 문자열을 원본 DB로 쓰지 않는다. 코스·계획을 수정하거나 저장 코스를 삭제해도 과거 운동의 사본은 바뀌지 않는다. 설정은 작은 JSON을 SharedPreferences에 저장한다.

코스 JSON 교환 형식:

```json
{
  "schemaVersion": 2,
  "course": {
    "id": "uuid",
    "name": "나의 코스",
    "version": 1,
    "points": [
      {"lat": 37.5, "lon": 127.0},
      {"lat": 37.501, "lon": 127.001}
    ],
    "pointIds": ["point-a", "point-b"],
    "paceTargets": [{"fromPointId": "point-a", "toPointId": "point-b", "paceSeconds": 360}],
    "paceTransition": "WAYPOINT",
    "usePaceTargets": true
  }
}
```

GPX 1.1은 외부 앱과의 좌표 교환에 적합하지만 런킵의 페이스 계획·목표 경계·심박수 원본 등 모든 의미를 보존하지 않는다. 코스·기록은 단일 내보내기 버튼에서 지원 형식/범위를 선택한다. 시스템 파일 선택과 쓰기 동안 중복 실행을 막고 선택 시점의 내용을 유지한다. 취소/실패 후 재선택할 수 있으며 완료/실패를 표시한다. 기록 GPX 전체/목표 범위는 화면 표시와 독립적이다. 운동 JSON은 전체 원본의 `schemaVersion`, `run`, `points`, `hearts`를 담는다. Flutter나 백엔드를 추가할 때 이 스키마를 변환해서 사용할 수 있다.

코스 가져오기는 v1 JSON·GPX 2MB, v2 JSON 8MB·10,000지점 제한을 적용하며 좌표 범위를 검증하고 XML 외부 엔터티/DTD를 거부한다. 여러 GPX segment를 강제로 직선 연결하지 않고 단일 연속 코스만 받는다. 운동 GPX는 일시정지·신호 공백을 별도의 segment로 내보낸다.

1. Z Fold + Fit3 실측 검증, 페이스/자동 정지 임계치 조정, 기록 장시간 성능 검증.
2. 운동 JSON 가져오기와 전체 백업/복원, 5km/10km 등 거리별 최고 기록, 폴더블 전용 화면.
3. 손으로 선 그리기, 실제 보행 경로 계산, 경로 이탈 후 중간 합류 정교화.
4. 온라인 코스 검색/공유, 오프라인 지도·통신 복구 정책.
5. 실시간 심박수, 트레드밀, 필요 시 Flutter.

경로 검색 서비스와 공유 백엔드, 새로운 유료 API는 선택하지 않았다. 해당 단계에서 비용·제약과 사용자의 요구를 확인한 뒤 결정한다.

## 운동 오디오 계약

### 음성 선택·조건·호환

`voice`는 앱 전체 음성, `paceVoice`는 목표 이탈 음성만 제어한다. 페이스 전체를 꺼도 길 안내·거리 현재·1km 평균·비음성 경보·메트로놈 설정은 바뀌지 않는다. `readPaceStatus` 기본 true, 기존 `readCurrentPace`/`readTargetPace` 기본 false로 기존 설정 JSON의 짧은 상태 안내를 보존한다. 세 하위 선택은 전체를 꺼도 저장되며 상태 없이 현재/목표만 읽는 조합까지 8조합을 지원한다. 모두 끄거나 선택한 유효 수치가 없으면 이벤트/빈 TTS를 만들지 않고 발화 타이머를 소비하지 않는다. 숫자는 기존 `paceSpeechText`를 사용하며 시각·콜론으로 읽지 않는다.

상태를 꺼도 현재/목표 안내는 **목표 이탈 조건에서만** 발생한다. 정상 범위는 계속 무음이다. 목표 없음·유효 페이스 없음·GPS 불량/만료·계획 완료 기본 정책·정지/종료에는 목표 이탈 안내를 만들지 않는다. 거리마다 현재값을 읽는 기능은 아래의 별도 설정이다.

음성 최초 이탈 지속은 10초, 재안내는 **실제 TTS onStart 기준 10~120초(기본 30초)**다. 생성/대기/실패 시각은 반복 간격을 소비하지 않는다. UI는 5초 단위, 저장/엔진은 범위 내 정수 초를 수용한다. 잘못된 반복 저장값은 30초로 복구한다. 방향 반전·수동/자동 정지·재개·같은 목표의 새 구간도 지속 시간을 다시 시작한다. 대기 경고는 매 평가에서 최신 수치 한 개로 갱신한다. 이미 시작한 문장은 정상 복귀·구간 변경·GPS 만료 때도 끝까지 말한다. 사용자 정지/종료·전체/페이스 음성 끄기·전화/외부 포커스 손실은 중단할 수 있다.

### 경보 판정과 추정 창

허용오차 바깥이면 다음 상태 평가에서 경보를 시작하거나 FAST/SLOW로 전환한다. 목표 360초/km·허용오차 10일 때 **350~370 경계 포함 정상**, 349.999/370.001은 이탈이다. 기존 추가 2초/km 진입 여유와 경보 2초 지속 조건을 제거했다. 음성의 10초 지속/반복과 분리하며 새로운 숨은 문턱으로 대체하지 않는다.

1초 타이머는 최신 유효 추정값을 평가하는 주기이며 매초 새 GPS/1초 페이스를 생성하지 않는다. 유효 위치 갱신 평가도 유지한다. 최근 약 20초 창·최소 8초/8m를 그대로 사용한다. 추정 창 후보 비교는 [합성 비교 조사](PACE_ESTIMATION_COMPARISON.md)에 있다. GPS 유효 나이는 10초이며 불량/튀는/지연된 위치, 제공자 중단, 만료는 경보와 대기 코칭을 지운다.

### 지속 메트로놈과 단일 출력

`metronome` 기본 false와 `paceAlarm` 기본 false는 독립적이다. 목표 `cadenceTargetSpm`은 기존 null 기본을 보존하며 null이면 180spm, 유효 범위는 120~220spm이다. 이 숫자는 기존 앱 입력/기본 정책이지 권장 또는 정답 케이던스가 아니다. 목표 박자는 양발을 합한 분당 걸음 수로 한 걸음에 한 비트다. 실제 걸음 센서의 최근 20초 측정 케이던스와 구분한다. 185spm의 이상적 간격은 60000/185 = 약 324.324ms다.

`BeatOutputPolicy`가 **단일 BeatSchedule**을 소유하고 `PaceAlarmPlayer`가 PCM 출력과 작업 수명을 소유한다. 단조시각 anchor와 비트 번호로 각 deadline을 반올림하여 매 비트의 반올림 오차를 누적하지 않는다. 늦은 콜백은 지난 비트를 건너뛰고 strictly future deadline으로 이동한다. 185spm에서 반올림된 지난 deadline을 다시 반환하는 경우도 막는다. 메트로놈 정상 CLICK은 2000Hz/20ms, FAST 1200Hz/70ms, SLOW 600Hz/70ms다. 경보+메트로놈은 한 비트에서 FAST/SLOW가 CLICK을 대체하며 정상 복귀·경보 만료는 같은 위상의 CLICK으로 돌아간다. 메트로놈을 꺼도 경보 단독은 가능하다.

RUNNING 메트로놈은 목표 박자 훈련이므로 GPS 코칭 만료와 구분해 계속 유지한다. 만료 경보는 플레이어에서도 제거한다. 수동/자동 일시정지·종료·서비스 종료는 모두 중단하며 재개 시 새 anchor에서 시작한다. 경보/메트로놈 음량은 공통 `paceAlarmVolume` 0~1(기본 0.5), 음성 음량은 별도로 유지한다. 사용자 미리듣기는 운동을 만들지 않으며 목표 박자, 180/185 비교와 빠름/느림을 제공하고 약 1초 뒤 명시적으로 stop한다.

### 거리별 현재 페이스

`distancePaceVoice` 기본 false, `distancePaceMeters` 기본 100. 정수 **10~10000m**를 UI 직접 입력/프리셋·저장 정규화·상태기에 동일하게 적용한다. 프리셋은 10/20/100/200/1000m, 잘못 저장된 값은 100m로 복구한다. 기존 `kilometerVoice` 값을 덮어쓰지 않는다.

현재값은 RunEngine의 최근 창 페이스이고 1km 안내의 운동 전체 누적 평균과 다르다. 목표나 페이스 이탈 음성이 꺼져 있어도 현재값이 유효하면 거리 안내는 동작한다. 경계는 **유효 운동 누적 거리의 배수**다. 준비 중/유효 수치 없음에 넘은 경계는 생략하고 나중에 과거 숫자를 읽지 않는다. 일시정지 중 드리프트·GPS 불량/만료·신호 공백·위치 튐은 운동 거리 필터를 그대로 거쳐 안내를 만들지 않는다. 정상 수신 복귀 후 준비 창을 다시 채우며 과거 경계는 되읽지 않는다.

설정 켜기/끄기·간격 변경·앱 전체 음성 켜기·운동 복구/재개는 현재 거리 이후의 **다음 배수**부터 적용한다. 값이 같은 설정 갱신은 경계를 재설정하지 않는다. 여러 경계를 한 번에 넘어도 한 이벤트만 만들며 대기 거리 이벤트는 종류별 최신 한 개로 합친다. 경계 발생 시각의 수명 15초를 유지하고 재생 직전까지 최근 유효 GPS 수치로 갱신한다. GPS 값이 만료되면 대기 현재값을 버린다. 10m를 선택해도 진행 중 문장을 강제로 끊거나 밀린 목록을 읽지 않는다.

상태→길 안내→구간/목표/1km→페이스 코칭 순서의 공통 AnnouncementQueue를 쓴다. 같은 GPS 수신에서 1km 평균과 거리 현재 경계가 겹치면 Kilometer 이벤트 하나에 평균·현재를 함께 읽고 대기 거리 현재 이벤트를 제거한다. 평균과 현재가 같은 숫자라고 의미를 바꾸지 않는다. 해당 현재 부분도 재생 직전 최신값을 사용하며 무효/정지/거리 옵션 끄기에는 현재 부분만 버리고 평균 이정표는 유지한다.

### 운동·포커스·샘플 수명

`RunService`는 모든 GPS·틱·설정·명령·발화 시작 콜백을 한 이벤트 채널로 통합한다. 새 START가 미완료 운동 없이 실제 새 운동을 생성할 때 `WorkoutAudioSession.attach(newWorkout=true)`로 이전 cue와 발화 요청을 초기화하고 기존 플레이어를 중단한다. 미완료 운동 복구는 동일 run ID의 표시만 유지하며 같은 운동 재개/화면 재진입에는 초기화를 적용하지 않는다. 엔진 identity와 오디오 세션/요청 token을 함께 검사해 이전 운동/요청의 늦은 TTS 콜백이 새 운동 반복 상태를 갱신하지 못한다. 새 운동의 표시 초기화는 이전 문장이 실제 재발화됐음을 입증하지 않는다.

운동 음성과 박자는 기존 공통 `RunAudioFocus`에서 플레이어별 사용권을 얻고 반환한다. 음성이 준비/재생 중이어도 비트를 억제하거나 두 번째 비트 타이머를 만들지 않는다. 마지막 소유자가 반환하면 OS 포커스를 해제한다. 전화/통신/벨 모드에는 새 소리를 요청하지 않는다. 일시 포커스 손실 후 gain에서는 최신 경보 신선도를 확인하고 놓친 박자를 몰아 재생하지 않는다. 영구 손실/이어폰 해제는 사용자 명시적 START/RESUME 또는 경보/메트로놈 껐다 켜기까지 비트를 차단한다. 자동 재개나 블루투스 재연결만으로 차단을 풀지 않는다.

경보/메트로놈 stop은 job·beat state·트랙·포커스를 해제하고 close는 수신기·scope까지 해제한다. foreground location service와 기존 partial wake lock을 사용한다. 화면 꺼짐/블루투스 실측은 순수 스케줄 테스트로 입증하지 않는다.

설정의 음성 미리듣기 범주, 샘플 완료/오류/명시 중지/이탈 상태와 사용자 시작 샘플만 적용하는 450ms debounce를 유지한다. 미종료 운동의 RUNNING/AUTO_PAUSED/PAUSED/INTERRUPTED 상태에서는 샘플을 차단한다. 페이스 예문은 선택한 항목만 읽고 모든 항목을 끄면 빈 샘플을 재생하지 않는다. simulation GPS 화면 정책과 공통 거리/계획 편집은 변경하지 않는다.
