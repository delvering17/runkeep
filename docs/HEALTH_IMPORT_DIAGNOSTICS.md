# 심박수 가져오기 진단

명시적 가져오기·실패/재시도와 내보내기 정책을 유지하며 심박수 조회의 빈 결과와 실패 원인을 구분한다.

## 확인한 코드 문제와 수정

| 문제 | 확인한 원인 | 수정 |
| --- | --- | --- |
| 페이지 조회가 완료되지 않거나 일부만 처리될 가능성 | 두 조회 루프가 종료 토큰을 `null`로만 판별하며 반복 토큰도 허용했다 | `null`과 빈 문자열에서 종료하고 같은 토큰을 다시 받으면 실패로 처리한다. 모든 페이지 성공 전에는 저장하지 않는다 |
| 후보 일부를 선택할 수 없음 | 화면에서 `take(20)`으로 잘랐다 | 모든 페이지의 삼성 출처·실제 교집합 후보를 중복 제거해 시간순으로 제시한다 |
| 선택 시간에 실제 샘플이 비었는지 알 수 없음 | 레코드·샘플·출처별 결과가 같은 빈 상태로 합쳐졌다 | 레코드 개수, 선택 구간 교집합, 유효 샘플 개수를 구분한다. 빈 결과에서 사용자가 진단을 누르면 런킵 전체 시간과 선택 교집합, 삼성·다른 출처의 개수만 비교한다 |
| 취소·권한 변경·읽기 실패가 섞임 | `runCatching`이 취소도 잡고 원문 예외를 UI에 표시했다 | 취소는 전파한다. 각 작업 직전에 availability와 두 읽기 권한을 재확인하고 단계별 실패 코드만 화면에 표시한다. 저장 실패도 읽기 실패와 구분한다 |
| 시간 경계 정밀도가 손실됨 | 세션·샘플 `Instant`를 교집합 계산 전에 밀리초로 변환했다 | 교집합과 필터는 `Instant`로 계산하고 DB 키로 저장할 때만 밀리초로 변환한다 |

페이지 종료 토큰의 빈 문자열 가능성은 Android 공식 원본 읽기 문서가 설명한다. 이 조건 또는 위 코드 문제가 사용자 기기에서 실제로 발생했다는 것은 아직 확인하지 않았다. 반복 토큰은 별도의 방어 조건이며 정상 제공자 동작이라고 단정하지 않는다.

## 읽기·저장 계약

- availability는 사용할 수 있음, 제공자 설치·업데이트 필요, 기기/프로필 미지원으로 나눈다.
- 심박수와 운동 읽기 권한만 사용한다. 기존 manifest/rationale 선언은 유지하며 쓰기·백그라운드·과거 데이터 추가 권한을 임의로 요청하지 않는다.
- 세션 조회의 기존 전후 1시간 범위를 보존하고, 삼성 출처와 런킵 시간에 실제로 겹치는 세션만 선택 후보로 남긴다. 후보 없음은 별도의 런킵 전체 시간 가져오기로 진행할 수 있다.
- 가져오기 조회는 선택 세션과 런킵 **전체 원본**의 교집합이다. 세션 미선택이면 전체 원본 시간이다. 목표 보기용 사본을 읽기 경계로 사용하지 않는다.
- 삼성 출처 필터를 유지하며 반환된 metadata도 다시 확인한다. 다른 출처 세션이나 심박수를 삼성 데이터로 저장하지 않는다.
- 요청/선택 범위는 시작 포함·끝 제외다. HeartRateRecord는 0 길이 구간과 레코드 끝 시각의 샘플도 표현할 수 있어 이를 무조건 버리지 않는다. 레코드 구간의 양 끝은 샘플 유효성 검사를 위해 포함하고 최종 선택 범위에는 끝 제외를 적용한다.
- 원본 구간 밖 시각이나 1~300 범위 밖 값은 제외하고 개수만 진단한다. 빈 구간을 보간하거나 샘플을 생성하지 않는다.
- 페이지/레코드 중복을 제거하며 DB의 기존 `(runId, sourceId, epochMs)` 키와 `@Upsert`를 유지한다. 재가져오기는 같은 키를 갱신한다. 서로 다른 원본 레코드를 시간만으로 합쳐 원본 의미를 바꾸지 않는다.
- 진단의 중복 레코드와 중복 샘플 개수는 구분한다. 같은 레코드를 다시 반환한 페이지를 샘플 중복으로 합산하지 않는다.
- 레코드 조회·변환은 IO 문맥에서 수행한다. 전체 읽기 30초 제한과 화면/기록 이탈 취소를 적용한다. 실패·토큰 만료·반복·시간 초과 때 부분 결과를 저장하지 않는다.
- UI 기본 상태는 가져오기 버튼 하나다. 실패나 실제 빈 조회 후에만 필요한 안내·재시도·진단을 제공한다. 진단은 저장하지 않으며 내보내기 UI/포맷도 변경하지 않는다.

## 진단의 한계와 공식 근거

[삼성 FAQ](https://developer.samsung.com/health/health-connect-faq.html)는 Samsung Health 6.22.5 이후 Health Connect 연동과 운동·심박수 지원, 삼성 앱에서 권한 설정 및 동기화 확인을 설명한다. Galaxy Watch 자료를 Fit3의 모든 데이터·이전 기록 지원 보증으로 확대하지 않는다. 삼성 헬스 앱에 기록이 보이는 것, 삼성 계정 동기화, Health Connect에 실제 레코드가 존재하는 것은 별개의 확인이다. 설정/권한 화면만으로 기존 기록이 전송됐다고 확정할 수 없다.

[Android 원본 읽기](https://developer.android.com/health-and-fitness/health-connect/read-data)는 페이지 토큰 처리, foreground 읽기, 권한/IPC/IO 예외, 최초 권한 부여 시점의 30일 이전 조회 제한과 history 권한을 설명한다. 런킵은 최초 권한 부여 날짜를 임의로 추정하지 않는다. `SecurityException`은 접근 제한으로 안내하며 과거 기록 제한·권한 철회·백그라운드 제한 중 하나로 확정하지 않는다. 조회 성공 0개도 저장소 전체에서 원본이 없다는 증거가 아니다.

[AndroidX HeartRateRecord](https://github.com/androidx/androidx/blob/androidx-main/health/connect/connect-client/src/main/java/androidx/health/connect/client/records/HeartRateRecord.kt)와 [TimeRangeFilter](https://github.com/androidx/androidx/blob/androidx-main/health/connect/connect-client/src/main/java/androidx/health/connect/client/time/TimeRangeFilter.kt)의 구간/샘플 타입을 함께 확인했다. 사용 중인 connect-client 1.1.0과 빌드 의존성은 변경하지 않는다. 합성 정책 검사는 실제 Health Connect 제공자의 반환 구간·과거 조회·동기화를 실행한 검사가 아니다.

진단은 사용자가 요청한 동일 운동 시간만 비교한다. 타 출처 자료는 저장하지 않고 운동 제목/출처 목록/레코드 ID/심박수 값/위치/계정/예외 원문을 로그·공개 댓글·예제에 출력하지 않는다. 후보의 기존 운동 제목은 앱 화면에서만 유지하며, 진단 화면에는 삼성/다른 출처 집계와 전체·선택 시간(초 단위)·시간대만 표시한다.

## 합성 검증과 자동 검사

전용 core 회귀 23개는 교집합·시작/끝 경계, 긴 레코드 내부 샘플, 0 길이/레코드 끝 샘플, 잘못된 원본 샘플, 밀리초 미만·UTC/KST 동일 시각, 세션 없음·25개 후보·중복, 외부 출처 차단, 빈/반복 토큰·여러 페이지, 재가져오기 DB 키, 선택 밖 삼성 샘플·다른 출처 비교, availability·권한 철회·접근 제한·후속 페이지 만료·실패·시간 초과 분류·취소 전파를 검사한다. simulation 소스셋의 전용 UI 상태 검사 3개는 필요한 안내·빈 결과·재시도 선택을 검사한다. 시간 초과 분류 검사는 합성 실패 입력이며 실제 제공자 응답 지연 측정이 아니다.

SQLite 메모리 DB에 저장소의 기존 `heart_samples` 스키마를 적용해 합성 자료의 같은 키 반복 저장, 값 갱신, 다른 원본 레코드 유지도 확인했다. 이는 Android Room DAO 실행 검증과 구분한다.

자동 검사 설정·범위와 공개 CI 상태는 [검증 기록](VALIDATION.md)에 정리한다. GitHub Actions는 JDK 25 / JVM 21 / JUnit 5에서 core·simulation 단위 테스트와 preview/kakao debug·simulation 네 variant 빌드·lint를 수행하도록 설정되어 있다.

실제 기기의 Health Connect 반환, Fit3→삼성 헬스→Health Connect 동기화, 권한 화면·터치·접근성·동일 기기 재가져오기는 미실행이다.

## 아직 확정되지 않은 단계와 최소 확인 자료

삼성 헬스에 기록이 보여도 Health Connect 실제 원본 존재·출처·시간 구간은 별도로 확인해야 한다. 코드와 합성 테스트만으로 동일 기기의 빈 조회 원인이 해결됐다고 판단하지 않는다. 진단 정책의 근거는 [HealthImportPolicyTest](../core/src/test/kotlin/com/runkeep/core/healthimport/HealthImportPolicyTest.kt)에 있다.

다음 비식별 자료를 확인하면 조사할 단계를 구분할 수 있다.

1. Android/삼성 헬스/런킵 버전과 가져오기 뒤 정확한 상태 문구.
2. 해당 운동에 대한 Health Connect 운동/심박수 항목의 존재 여부와 출처가 삼성 헬스인지 여부. 원본 bpm·위치·계정 화면은 필요 없다.
3. 런킵 진단의 삼성/다른 출처 개수, 전체/선택 샘플 개수, 페이지 개수. 시간은 운동 시작 대비 상대 시각과 시간대만으로도 우선 비교할 수 있다.
4. 런킵 두 읽기 권한과 삼성 헬스 운동/심박수 쓰기 권한의 허용 여부, 최초 런킵 읽기 권한 부여일과 운동일의 간격.

삼성 원본 존재를 런킵 내보내기만으로 증명하지 않는다. 필요성이 확인되기 전에는 원본 건강/위치 JSON이나 그래프 전체를 추가 요청하지 않는다.
