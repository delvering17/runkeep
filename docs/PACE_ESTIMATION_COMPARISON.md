# 고정 합성 기준의 페이스 추정 창 비교

## 결론

**이 합성 비교는 기본 20초·최소 8초/8m 유지, 사용자 창 설정 보류를 지지한다.** 최적값을 입증한 결과는 아니다. 20초는 10초 인터벌에 느리지만 5초로 단순 축소하면 작은 좌표 잡음에서도 ±10초/km 경계를 빈번하게 넘었다. 추가 경보 문턱/지속을 제거한 모델과 추정 자체의 지연을 분리해서 읽어야 한다. 이 문서는 고정 모델의 실험이며 현재 공개 앱의 정확도나 기기 실행 결과가 아니다.

10초는 다음 비교의 유력 후보이고 5초는 그대로 배포할 근거가 부족하다. 30초는 일부 잡음에서는 가장 안정적이지만 변속 반응은 더 늦다. 시간 가중 평활화도 거리 계산에 이미 들어간 양의 잡음 편향을 제거하지 못했다. 제공자 속도는 연구할 가치가 있으나 합성 센서값의 좋은 성적을 실제 폰의 성능으로 취급할 수 없다.

## 재현 방법과 파일

저장소 루트에서 Python 3.12의 표준 라이브러리만 사용한다. JDK 25/JVM 21/JUnit Jupiter 5는 기존 Gradle/CI 설정을 그대로 사용한다. [JUnit 재생 테스트](../core/src/test/kotlin/com/runkeep/core/analysis/PaceComparisonReplayTest.kt)는 합성 관측을 RunEngine에 넣어 모델의 activeMs·meters·segment·currentPace와 비교하도록 작성되어 있다. 고정 실험과 현재 엔진 사이의 비교 범위는 테스트 소스가 정의하며 이 문서는 공개 커밋의 테스트 성공을 주장하지 않는다.

```sh
python3 tools/pace_comparison/compare.py
python3 tools/pace_comparison/compare.py --check
python3 -m unittest discover -s tools/pace_comparison -p 'test_*.py' -v
./gradlew :core:test --tests 'com.runkeep.core.analysis.PaceComparisonReplayTest'
```

- [scenarios.json](../tools/pace_comparison/scenarios.json): 21개 작은 시나리오 정의. seed에 의존하는 난수 없이 좌표/시간/제공자 속도를 결정적으로 생성한다. 동일 입력을 모든 후보/정책에 사용한다.
- [compare.py](../tools/pace_comparison/compare.py), [test_compare.py](../tools/pace_comparison/test_compare.py): 생성·운동거리 필터·후보·정책 모델과 의미 있는 불변조건 검증.
- [results.csv](../tools/pace_comparison/results.csv): 21×11 후보의 오차·유효 비율·수렴·경계 왕복·경보 횟수.
- [metadata.json](../tools/pace_comparison/metadata.json): baseline SHA·fixture SHA-256·거리/거부 횟수·가상 오디오 가정.
- [timelines.json](../tools/pace_comparison/timelines.json): 대표 입력의 경보 시작/중단·음성 적격·가상 요청/시작 시각. raw 좌표 전체는 저장하지 않는다. `--trace`로 필요할 때 생성한다.

## 측정 구조와 공정한 조건

truth는 입력한 piecewise 속도의 순간값이며 해당 속도를 적분한 좌표에 잡음을 더한다. `t=60`에서 속도를 바꿔도 `59→60` 선분의 거리는 이전 속도 구간이다. truth 속도를 그대로 현재 페이스 기대값으로 넣지 않는다. 위도 0의 짧은 합성 직선이고 WGS84 구면 Haversine 상수는 실제 엔진과 같다. 포물선·도심 다중경로·실측 오차 분포를 모델링한 데이터는 아니다.

raw_polyline은 정확도와 순서·수신을 통과하고 RUNNING 중인 좌표를 단순 연결한 참조 거리다. 점프·이동 판정·0.8m 절삭·긴 공백/정지 segment 단절 전에 비교하며, 공백을 직선으로 연결하므로 기록용 정답이 아니다. recorded_m는 실제 운동거리 필터를 지난 누적 거리다. 모든 좌표 후보는 이 recorded_m와 같은 activeMs를 공유한다. 제공자 속도 후보도 같은 수신·정확도·점프·준비 조건을 통과한 위치에서만 평가한다.

- 정확도 >25m/음수/비유한 값, 수신 나이 >3초는 폐기·창 초기화. 미래/오래된 순서 입력은 무시한다. 서비스의 별도 >10초 폐기보다 엔진 3초 수신 검사가 엄격하다.
- 15초 미만 선분 속도 >12m/s는 점프 폐기. 이 경로는 표시를 무효화하지만 baseline 창/lastFix는 남긴다. 다음 정상 수신이 옛 anchor를 사용할 수 있는 점도 실제 엔진 대조에 포함한다.
- 제공자 speed≥0.7이면 이동, speed 없음은 좌표 이동>max(2.5m, accuracy/2). 유효 선분 ≥0.8m만 누적. >15초 공백·정지/재개는 segment를 나누고 연결 거리를 더하지 않는다.
- 마지막 유효 위치 나이 >10초인 타이머 평가에서 창/현재값이 초기화된다. 타이머는 새 표본을 만들지 않는다. 불량 위치는 즉시 무효화한다.
- 자동 정지는 전 후보에서 **끔**으로 고정해 추정 후보와 자동정지 판정을 혼합하지 않는다. 수동 pause/resume은 동일 시점에 적용한다. 자동 정지/재개 알고리즘 자체는 기존 별도 테스트가 담당하며 이번 비교에서 바꾸거나 성능을 검증하지 않았다.
- 1초 tick과 위치 이벤트를 시간순으로 넣되 같은 시각에는 제어→위치→tick 순서다. 실제 비동기 서비스의 OS 예약 지연/모든 교차 순서를 재현한 것은 아니다. 불규칙 위치는 0.5/1.5/4/1/3초 반복, sparse는 4초 간격이다.

창 밖의 첫 관측점을 제거하며 창 경계를 보간하지 않는다. 따라서 30초 설정과 4초 갱신에서는 실제 시간 범위가 28초가 될 수 있다. 창 길이와 최소 준비시간은 다른 값이다. 5초/8초는 유효값 0%이며 5초/4초가 빨리 준비되는 이득을 창 길이 개선으로 포장하지 않는다. 4초 대조군은 정상 준비 이후 기존 후보와 같은 값이므로 변화 수렴 비교는 충분히 준비된 40/60초 이후를 사용한다.

MAE는 RUNNING이며 truth>0인 1초 평가 중 표시 가능(0<s/km≤3600)한 값의 절대오차 평균이다. 유효 비율의 분모에는 시작·불량·공백·재준비 시간을 포함하고 수동 정지 시간은 제외한다. 제자리 truth는 무한 페이스이므로 MAE/이동 유효 비율은 N/A로 두고 허위 경보/거리로 판단한다. 분모는 t=0과 끝 시점도 포함한 1초 관측 수다. 결측을 오차 0으로 취급하지 않는다.

수렴은 변경된 truth의 ±5%에 **3회 연속 1초 평가**가 들어오는 첫 시점이며 다음 변경 전 미충족이면 null이다. 완전한 창 교체 시간과 다르다. 우연히 범위에 들어오거나 바이어스가 상쇄될 수 있어 수렴만으로 순위를 매기지 않는다. 경계 전환은 FAST/NORMAL-or-invalid/SLOW 상태 변화 횟수, round_trips는 이탈 상태에서 NORMAL-or-invalid로 복귀한 횟수다. 무효화 복귀도 포함하므로 품질 시나리오에서는 반드시 유효 비율을 함께 읽는다. false_outside는 정상/정지 truth의 오경보 초 수, wrong_direction은 truth와 다른 방향의 모든 이탈 초 수다. 불필요 경보 시작은 truth 정상·정지 또는 반대 방향에서 시작/전환한 횟수이며 오디오 비프 개수가 아니다.

## 경보와 음성 지연 분리

| 정책 버전 | 이탈 진입 | 비음성 경보 | 음성 | 반복 |
| --- | --- | --- | --- | --- |
| legacy_9500d1f | 허용오차 ±10초/km 바깥 + 재진입 2초/km | 같은 방향 2초 후 | 같은 방향 10초 후 적격 | 실제/가상 시작 기준 기본 30초, 허용 10~120초 |
| issue34_proposed | 허용오차 ±10초/km 바깥 | 다음 평가에서 즉시 | 같은 방향 10초 후 적격 | 기존 반복 유지 |

`legacy_9500d1f`는 고정 실험의 기존 정책 식별자다. `ENTRY_MARGIN_SECONDS=2`, `ALARM_SUSTAIN_MS=2000`, `VOICE_SUSTAIN_MS=10000`, 기본 반복 30초를 사용한다. `issue34_proposed`는 추가 진입 문턱과 경보 지속을 제거한 비교 모델 식별자다. CSV와 재현 소스의 이름을 그대로 유지하며 공개 이슈 번호나 현재 앱 버전으로 해석하지 않는다. GPS 갱신 이벤트와 1초 tick 모두 평가하며 새 위치 없는 tick은 최신 유효값을 다시 평가할 뿐이다. 모델 목표는 고정 360초/km, 정상 경계는 350~370 포함이다.

20초 후보의 깨끗한 420→300 변속(t=60) 예:

| 구분 | legacy | 문턱 제거 모델 모델 |
| --- | ---: | ---: |
| 느림 경보 중단/정상 범위 진입 | 67초 | 67초 |
| 빠름 경보 시작 | 73초 | 70초 |
| 새 속도 ±5% 수렴 | 77초 | 77초 |
| 빠름 음성 적격 | 82초 | 82초 |
| 가상 재생 요청 | 82초 | 82초 |
| 가상 발화 시작 | 84초 | 84초 |

범위를 넘는 시점과 ±5% 수렴 시점은 다르다. 문턱 제거 모델 모델은 추가 지속 2초와 진입 여유를 제거해 이 예의 경보 시작을 3초 앞당겼지만 창의 수렴 17초는 바꾸지 않았다. 음성은 10초 지속 외에도 이전 가상 발화 시작 52초+30초 반복 제한 때문에 82초에 적격이 됐다. 실제 음성에서는 다른 안내·오디오 포커스·TTS 준비/발화 길이에 따라 더 늦을 수 있다.

가상 오디오는 요청 수락 즉시 기록, 요청→시작 2초, 문장 4초, 60~68초 다른 안내 점유, 재안내 기본 30초를 **가정**한다. virtual_request/virtual_start는 실제 서비스/TTS 측정이 아니다. 적격만 먼저 생기면 점유 해제 후 요청하며, 시작 시간에만 반복 시간을 소비한다. 예를 들어 수치 420이 계속되는 별도 정책 검사에서 8~24초 점유를 가정하면 적격 10초→가상 요청 24초→가상 시작 26초가 된다. 실제 발화 시각은 모든 실험에서 미측정이다. 10/30/120초 반복 끝값은 재현 불변조건 테스트로 분리 확인한다.

## 센서 속도와 다음 단계 판단

기본 합성 speed는 truth+0.03m/s sine이며 좌표 잡음과 독립이다. 이 소스는 의도적으로 좋은 가능성 예시다. bias +0.3m/s에서는 센서 MAE 28.785초/km이고 새 300초/km 구간에 수렴하지 못했다. 0.3m/s 잡음과 speed 결측도 별도 CSV에 있다. 결측에서는 sensor 유효 비율 0%, 좌표 후보도 speed 미제공 시 이동 필터가 달라 거리 손실이 생긴다. 소스의 가용성/오차 가정을 숨기고 센서로 교체하면 안 된다.

현재 LocationFix/RunService는 speed를 전달하지만 speed accuracy는 전달하지 않는다. 센서 기반 후속 구현이 필요해지면 hasSpeed/hasSpeedAccuracy·단위·신선도·비유한/음수·불확실성 문턱·좌표 추정 fallback을 먼저 정의해야 한다. 제공자 speed를 기록 거리 적분에 바로 사용하거나 평균/랩 값을 바꾸는 변경과 분리한다. 배터리 영향은 공급자 요청 변경과 앱 추정 연산을 나눠 실측해야 한다.

이번 결과는 **기본 유지, 사용자 설정 보류**를 지지한다. 현재 앱의 문구·반복·경보 계약은 [설계](DESIGN.md)에 별도로 설명한다. 추정 변경이 필요하다는 실측 근거가 생기면 별도 후속 구현에서 다음 계약을 제안한다.

- 기본 20초, 우선 검토 범위 10~30초; 5초는 충분한 GPS 품질과 독립 준비시간 근거가 있을 때만 확대한다. 잘못 저장된 값은 20초로 정상화하고 기존 저장값 없음도 20초로 복원한다. 이 범위는 제안이며 이번에 추가된 사용자 설정이 아니다.
- 준비 조건 8초/8m를 창과 별도 필드로 유지한다. 허용 창보다 준비시간이 큰 조합은 거부한다. 모든 box에 같은 준비 조건의 민감도와 정상상태 지연을 회귀 검증한다.
- 운동 중 변경은 명시적 적용 시점에 창·대기 코칭/방향 지속을 초기화하고 새 표본으로 준비한다. active time·누적 거리·전체/랩 통계를 초기화하지 않는다. 이미 시작한 문장 처리와 반복 정책은 현재 음성 반복 계약에 맞춘다.
- 화면과 코칭은 우선 같은 추정값을 유지한다. 별도 빠른 화면/안정 코칭 값은 표시 의미·source age·지연의 사용자 이해와 실측 이득이 확인된 경우만 분리한다. 케이던스/자동정지의 20초·임계치는 함께 바꾸지 않는다.
- 야외 후속 검증은 같은 세션 raw 좌표/제공자 speed·speed accuracy·수신 나이·수동 lap 기준을 후보에 동시에 재생한다. 일정속도/10~30초 인터벌/목표 경계/신호 복귀와 화면 켬·끔, 실제 음성 요청·onStart/onDone, 이어폰/통화, 배터리를 별도 측정한다. 실측 기기 자료는 이 비교에 포함하지 않았다.

위 현장 확인은 production 변경을 결정할 때 필요한 추가 증거다. 미실행 확인을 완료 증거로 쓰지 않는다.

## 검증과 한계

21×11×2 정책의 CSV 결과와 재현 불변조건은 고정 모델의 조사 자료다. 이 공개 전환 작업에서 Python·JUnit·빌드·lint를 실행하지 않았다. 현재 공개 CI 상태는 [검증 범위](VALIDATION.md)에서 확인한다. 합성 실험의 결과를 현재 `main`의 실측 정확도로 해석하지 않는다.

합성 주파수·위상·한 직선에 민감한 결과이며 모집단 정확도·실측 GPS·워치 비교·야외 러닝·배터리·폰/이어폰 사용자 경험·실제 TTS 시작/완료·에뮬레이터 검증은 수행하지 않았다. 평균 오차 하나로 결론을 내리지 않고 준비/유효 비율, 거리 편향, 변속 지연, 경계/불필요 경보와 정책 버전을 함께 제시한다.
