# 운동 진단 기록

설정 → 측정·위치 → 진단 기록에서 켭니다. 기본값은 꺼짐입니다. 운동 중에도 변경할 수 있으며 상태 문구는 설정과 진행 화면에 표시됩니다. 위치 수신·처리·공백·정지·지도 사건은 자동 기록합니다. 사용자가 문제 시점을 표시할 필요가 없습니다.

이 기능은 #10의 조사 자료 수집 기능입니다. #9의 터널 표시 정책이나 거리·페이스·위치 필터 기준을 변경하지 않습니다. 기존 실제 운동의 분석, 서버 업로드, 원격 조회는 포함하지 않습니다.

## 수집 범위

- 운동마다 내부 파일을 분리합니다. Room 스키마는 version 1을 유지합니다.
- 켤 때마다 별도의 수집 session과 시작 사건을 만듭니다. 끄기·정상 종료·서비스 중단은 종료 사유를 남깁니다. 재시작 후 복구는 새로운 session과 복구 사건으로 표시합니다.
- 강제 프로세스 종료에서는 마지막 사건이나 메모리 큐가 저장되지 않을 수 있습니다. 종료가 확인되지 않은 session은 불완전으로 표시하며 유실 개수를 추측하지 않습니다. 미수집 구간의 위치나 사건을 과거 운동에서 복원하지 않습니다.
- 앱 버전·버전 코드·빌드 종류·지도 flavor·Android API, 실제 엔진의 자동 일시정지·회전 거리 설정과 코스·계획 사용 여부만 기록합니다. 운동 이름·코스 내용·전체 Preferences·RunSummary는 진단에 직렬화하지 않습니다.
- 위치 콜백 수신은 controller 단계에 기록합니다. 정확도 누락·시간 역전으로 controller에서 제외한 경우도 사유를 남깁니다. 기존 StateFlow가 연속 콜백을 합칠 수 있으므로 controller 통과는 엔진 채택을 뜻하지 않습니다. 이후 service와 engine 사건을 함께 확인합니다.
- service의 10초 초과 지연·재개 이전 샘플 제외와 engine의 시간·상태·정확도·위치 튐·자동 정지 대기를 실제 분기에서 구분합니다. service_to_engine의 FORWARDED는 엔진으로 전달했다는 의미이고, engine의 ACCEPTED가 기록 채택입니다.
- 정확도·제공 속도·속도 정확도는 제공된 유한 값만 포함합니다. 속도가 없을 때 이동 거리로 제공 속도를 만들어 넣지 않습니다. 위치 epoch도 절대 시각 대신 운동 시작에 대한 차이만 남깁니다.
- 10초 초과 콜백 미수신과, 수신했지만 정확도·위치 튐으로 제외한 상태는 독립적으로 기록합니다. 수신 재개와 유효 품질 복귀도 구분합니다.
- segment 사건에는 최초 위치, 정확도 제외 후 재연결, 15초 초과 공백, 수동·자동 재개 등의 실제 사유를 넣습니다. 수동·자동 정지·재개·종료·중단은 상태 사건으로 구분합니다.

## 지도 관찰

진행 지도와 기록 지도를 구분합니다. 지도 미열림, 열림·닫힘, SDK 미준비·오류·파괴, 갱신 호출 적용·실패, preview 그리기 완료를 기록합니다. 기록 지도 관찰은 진단 설정이 켜져 있고 해당 운동의 기존 진단 자료가 남아 있을 때만 추가됩니다. 진단이 없던 운동의 과거 사건을 만들지 않습니다.

전달한 track segment 수·점 수·계획 점 수를 기록합니다. 점 하나뿐인 segment는 입력 개수에는 포함되지만 선으로 그려지지 않습니다. 변경이 필요 없으면 UPDATE_UNCHANGED로 구분하고 실제 생성·변경·제거 호출 완료 개수도 남깁니다. 실패 시 이미 완료한 호출 개수는 유지합니다. 카카오의 UPDATE_APPLIED는 준비된 SDK에 대한 경로 생성·변경·제거 호출이 예외 없이 완료됐다는 뜻입니다. 실제 픽셀 표시·지도 인증·사용자가 본 화면까지 보장하는 값은 아닙니다. preview의 PREVIEW_DRAWN은 Canvas 그리기가 끝났을 때만 남깁니다. 준비되지 않았거나 열리지 않은 지도를 성공으로 표시하지 않습니다. 진단 콜백 예외는 지도 처리로 전파하지 않습니다.

## 파일 형식 v1

운동 상세 → 더보기 → 진단 자료 저장·공유에서 수집 횟수·시간 범위·포함 정보·유실 여부를 확인합니다. JSON 파일 하나를 Android 문서 선택기로 저장하거나 기본 공유 화면에 전달합니다.

| 필드 | 의미 |
| --- | --- |
| format / schemaVersion | runkeep-diagnostic / 1 |
| coordinatesIncluded / coordinateScope | 좌표 포함 선택과 범위 |
| coverage / mapResultScope | 수집 구간 및 지도 결과 해석 범위 |
| loss | 큐 누락 수, 저장 실패, 용량 한도, 손상, 종료 미확인 |
| events[].session / sequence | 수집 session 식별자와 해당 session 내 순서. session은 무작위 진단용 값이며 기기·계정 식별자가 아님 |
| atMs | session 시작에 대한 단조 시각 차이 |
| runOffsetMs | 운동 시작에 대한 상대 시각. session 시작 때의 벽시계 차이에 단조 경과를 더함. 재부팅·시계 변경 사이 절대 연속성은 보장하지 않음 |
| measurementEpochOffsetMs | 위치가 제공한 epoch와 운동 시작 epoch의 차이 |
| measuredAtMs / receivedAtMs / delayMs / processingDelayMs | 단조 기준 측정·콜백 수신 상대 시각, 측정→수신 지연, 수신→처리 대기 |
| kind / stage / reason | 사건 종류·처리 단계·실제 분기 사유 |
| pointIndex / segment / activeMs / meters | 채택 지점의 전체 운동 내 인덱스와 당시 결과 상태. 기존 운동 JSON의 points 인덱스와 연결 가능 |
| coordinate | 좌표 포함을 선택했을 때 관찰한 샘플 좌표만 존재 |
| mapSurface / trackSegments / trackPoints / plannedPoints | 진행·기록 지도 구분 및 전달 개수 |
| environment | 전용 허용 목록으로 구성한 버전·측정 설정 |

기록 지도 사건은 운동 종료 후의 별도 관찰이며 단일 사건 session, runOffsetMs로 시점을 표시합니다. 수집 session의 사건처럼 운동 중 발생했다고 취급하지 않습니다. 값이 없으면 필드도 생략합니다. 단조 시각이 이전 수집 시작보다 앞서는 지연 샘플은 음수 상대 시각을 가질 수 있습니다.

좌표 포함은 기본 꺼짐입니다. 좌표 제외 직렬화는 모든 사건에서 coordinate 필드 자체를 제거합니다. 메타데이터·코스·결과 요약에 좌표를 우회 저장하지 않습니다. 좌표 포함 시에도 관찰한 위치 샘플만 포함하고 기존 경로나 코스 좌표를 합치지 않습니다. 심박수·체중·계정·기기 식별자·키·개인 파일 경로는 선택에 관계없이 제외합니다. 기존 GPX·운동 JSON 형식은 변경하지 않습니다.

## 저장·삭제·공유 정책

- 메인 스레드는 256개 제한 큐에 비차단으로 넣습니다. 별도의 IO 작업자가 직렬화·파일 저장·용량 정리를 수행합니다. 큐 초과나 디스크 오류가 운동 처리를 중단시키지 않습니다.
- 운동당 진단 본문은 최대 4 MiB, 내부 진단 전체는 최대 32 MiB입니다. 유실 표시용 작은 sidecar를 위한 공간을 예약합니다. 전체 한도에서는 오래된 다른 운동의 진단부터 지우고, 현재 파일 한도에 도달하면 추가 사건 저장을 중단합니다.
- 마지막 기록으로부터 14일 지난 진단은 앱 시작·읽기·추가 기록의 정리 시 삭제합니다. 운동 DB에 없는 고아 자료는 앱 시작 시 정리합니다. 앱이 실행되지 않는 동안 시간 기반 정리는 실행되지 않습니다.
- 큐 누락·저장 실패·한도 도달은 상태 문구와 내보낸 loss에 표시합니다. 불완전 JSON 행은 건너뛰되 파일 손상을 표시합니다. 디스크 쓰기 자체가 불가능하면 유실 표시의 영구 저장도 보장할 수 없으며, 같은 프로세스에서는 메모리에 남겨 내보냅니다. 재시작 후 종료 미확인으로 미상 손실을 표시합니다.
- 내보내기는 앞선 큐 처리를 기다린 일관된 사본으로 수행합니다. 이 대기는 내보내기 작업에만 적용되며 운동 처리는 기다리지 않습니다.
- 운동 삭제는 진단과 관련 공유 임시 사본을 먼저 지운 뒤 기존 운동 삭제 트랜잭션을 실행합니다. 파일 삭제가 실패하면 운동 삭제도 실패로 안내하고 재시도할 수 있습니다. DB 삭제가 실패하면 운동은 남고 진단은 먼저 삭제됐을 수 있습니다. 종료된 운동에서는 진단만 별도로 삭제할 수도 있습니다. 삭제 이후 대기 중인 사건은 파일을 다시 만들지 않습니다.
- FileProvider는 diagnostic-shares 하위만 공개하며 외부 공개 provider가 아닙니다. 공유에는 content URI와 임시 읽기 권한만 부여합니다. 다른 캐시·운동 DB·내부 진단 원본을 공유 경로로 열지 않습니다.
- 공유 임시 사본은 최대 2개입니다. 1시간이 지나면 앱이 실행 중일 때 분 단위 정리, 앱 재시작, 다음 공유 때 삭제합니다. 공유 실행 실패 시 해당 사본도 삭제합니다. chooser 종료 결과로 전달 성공을 단정하지 않습니다. 대상 앱의 비동기 읽기를 위해 chooser가 닫힌 즉시 사본을 지우지는 않습니다.
- 외부 저장·공유가 끝난 파일은 대상 앱이 관리합니다. 문서 저장 실패 시 부분 파일이 남을 수 있음을 안내합니다. 기본 공유 화면의 취소·종료는 전송 완료로 보고하지 않습니다.
- ViewModel이 준비·문서 선택·쓰기·공유 상태를 보관해 화면 재생성 및 중복 클릭을 처리합니다. 프로세스가 사라져 원본 사본이 없는 문서 결과는 다시 내보내도록 안내하고 성공으로 표시하지 않습니다.

## 검증 범위

합성 단위 테스트는 실제 engine 분기, service 제외 우선순위, 수신·품질 상태, 지도 sink 성공·실패·관찰자 예외, 좌표 제거·직렬화, 기본 꺼짐·중간 전환·복구, 큐 초과·저장 오류·손상·용량·보관·삭제, 공유 캐시, 문서 쓰기 실패, 내보내기 상태 전환을 검사합니다. 자동 빌드·lint 및 테스트 결과는 PR의 검증 항목에서 확인합니다.

실제 휴대폰, Android 문서 provider·공유 대상 앱, 카카오 인증·화면 표시, 야외 GPS·개인 운동 데이터는 자동 합성 테스트의 검증 범위에 포함되지 않습니다.
