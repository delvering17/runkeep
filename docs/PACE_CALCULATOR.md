# 거리·전체시간·페이스 계산기

계획 편집 화면 하단의 `계산기`를 누르면 같은 구간 목록 안에 두 값의 공통 입력이 펼쳐진다. 계산 결과와 선택 구간의 현재 값·적용 후 값은 하단 요약에서 비교한다. `계산 입력`은 입력 위치로 다시 이동한다. 구간을 누르면 적용 대상을 선택하며 순서를 바꿔도 편집용 안정 ID를 유지한다. 선택 구간을 삭제하면 적용이 비활성화되고 다른 구간을 직접 선택해야 한다.

| 계산 | 입력 | 결과 |
| --- | --- | --- |
| 페이스 | 거리 m + 전체시간 s | 전체시간 × 1000 / 거리, s/km |
| 전체시간 | 거리 m + 페이스 s/km | 거리 × 페이스 / 1000, s |
| 거리 | 전체시간 s + 페이스 s/km | 전체시간 × 1000 / 페이스, m |

예시 버튼은 `10km · 1시간 → 6:00/km`, `5km · 30분 25초 → 6:05/km`다. 전체시간은 시/분/초, 페이스는 분/초 per km로 서로 다른 공통 바텀시트를 사용한다. 입력 범위는 기존 정책과 같다: 거리 양수~200km, 전체시간 1~12000초, 페이스 120~1800초/km. 새 시간·페이스 입력은 정수 초다. 입력 시트의 적용은 계산 입력만 바꾸며 계획 구간을 변경하지 않는다. 시트 취소는 계산 입력의 직전 값을 유지한다.

`선택 구간에 적용`만 계획 초안을 변경한다. 거리 기준 구간에는 계산 거리(m)와 정수 페이스(s/km), 시간 기준 구간에는 계산 전체시간(s)과 정수 페이스를 넣는다. 구간 종류·이름·다른 구간·계획 이름은 유지한다. 적용 후에는 기존 구간 계산식으로 예상 거리·시간·거리 가중 평균을 재계산한다. 반올림 때문에 계산의 원래 거리·시간과 예상값에 차이가 있으면 적용 후 요약과 저장된 구간 값이 기준이다.

계산 내부는 BigDecimal DECIMAL128 나눗셈을 사용하고 기존 모델의 Double m/s로 결과를 전달한다. 거리 소수는 최종 Double 저장 정밀도까지 보존한다. 시간·페이스는 초 단위 HALF_EVEN 반올림이며 기존 `paceText`의 동률 반올림과 같다. 반올림 전 범위를 먼저 검사하므로 119.99초/km를 120으로, 12000초 초과 시간을 12000으로 조용히 보정하지 않는다. 계산 결과가 시간 200분을 넘어도 거리 기준 구간에는 적용할 수 있으며, 시간 기준에는 적용할 수 없다. 페이스가 2:00~30:00/km 밖이면 두 종류 모두 적용할 수 없다. NaN·Infinity·0·음수·빈 입력과 Double로 표현 불가능한 결과·0으로 소실되는 결과는 거부한다. 큰 결과는 제한된 기존 페이스 포매터 대신 전용 포매터로 표시한다.

`계산 취소`는 계산 입력과 선택만 버린다. 계산 중에는 구간을 자동 덮어쓰지 않는다. 적용 직후 `실행 취소`는 적용 전 초안을 복구한다. 편집 화면의 변경 버리기는 저장된 원본을 유지한다. 최종 `계획 저장`에서만 기존 저장 API로 DB에 반영한다. 직렬화한 계산 입력과 선택 ID, 계획 초안은 구성 변경 복원에 사용하고 편집용 ID는 저장 계획 형식에 추가하지 않는다.

계산 입력은 스크롤 가능한 목록 안에 배치하고 결과 요약은 별도 스크롤 영역, 계산 적용·계획 저장 버튼은 고정 하단에 둔다. 공통 시트의 IME/safeDrawing 여백·줄바꿈·큰 글꼴 배치와 최소 48dp 터치 높이를 재사용한다. 기존 구간 드래그·자동 스크롤·접근성 이동을 유지한다.

이 문서는 계획의 선택 구간에 적용하는 계산기를 설명한다. 코스 편집에서 계산 페이스를 지점 간 연결에 적용하는 정책은 [코스·페이스 통합](COURSE_PACE_INTEGRATION.md)에 정리한다.

## 검증

`PaceCalculatorTest`는 세 방향 예시·소수 거리·큰값/비정상값·초 경계/동률 반올림·공통 입력 범위·종류별 적용 범위·삭제/순서 변경/복제/반복·적용 취소/undo·원본 보존·직렬화/최종 저장 후 재열기·총량 계산을 검증한다.

자동 검사 설정·범위와 공개 CI 상태는 [검증 기록](VALIDATION.md)에 정리한다. GitHub Actions는 JDK 25 / JVM 21 / JUnit 5에서 core·simulation 단위 테스트와 preview/kakao debug·simulation 네 variant 빌드·lint를 수행하도록 설정되어 있다.

UI 실행·실기기·에뮬레이터·큰 글꼴/TalkBack 실낭독은 미실행이다. 소스 구조 검토와 자동 검사를 실제 표시/터치 검증으로 간주하지 않는다.
