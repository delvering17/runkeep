# 모바일 UI와 입력 규칙

## 적용 범위와 호환성

`Root`, 달리기·코스·계획·기록·설정 화면에서 공통 기반을 사용한다. 코스 지점별 목표와 계산기 도메인 기능은 [코스·페이스 통합](COURSE_PACE_INTEGRATION.md), [계산기](PACE_CALCULATOR.md)에 별도로 설명한다. DB 스키마, 측정 서비스, 계획 구간의 m/s/s·km⁻¹ 저장 의미를 유지한다.

Compose BOM 2025.04.01의 Material 3 `ModalNavigationDrawer`, `NavigationRail`, `ModalBottomSheet`, `BottomSheetScaffold`와 Foundation `FlowRow`를 사용한다. 창 크기에 따른 조작 원칙은 아래 공식 근거를 따르며 기존 창 정보·Material 3 API로 구현한다.

## 내비게이션·창 크기

- 폰의 핵심 네 탭은 하단에 둔다. 중복 햄버거 드로워는 제거하고 계획은 달리기, 현재 위치·음성·데이터/권한·simulation 테스트는 설정의 기존 진입을 사용한다.
- `mobileWindow()`는 `LocalWindowInfo.containerSize`와 현재 밀도를 사용한다. 물리 기기 이름이나 방향으로 분기하지 않아 멀티윈도우의 실제 사용 가능한 창을 따른다.
- 폭 600dp 이상·높이 480dp 이상에서는 네 탭을 레일로 옮긴다. 1.8배 이상 큰 글꼴은 레일의 좁은 라벨을 피하도록 하단 탭을 사용한다. 높이가 작은 가로 창도 하단 탭을 사용한다.
- 폭 840dp 이상·높이 480dp 이상에서 달리기·코스·확대 기록 지도와 360dp 정보 패널을 나란히 표시한다. 다른 창에서는 표준 바텀시트다. 실제 힌지/접힘 자세 감지나 모든 화면의 두 패널 전환은 후속 범위다.
- 화면 ID와 초안은 `rememberSaveable` 및 Root의 `SaveableStateHolder`가 보관한다. 탭 이동, 폰/Fold 크기 변경, Activity 재생성으로 입력값이 바뀌지 않는다. 코스 저장/취소 후에는 해당 편집 상태를 제거한다.

## 패널·뒤로 가기·초안

| 종류 | 공통 API | 정책 |
| --- | --- | --- |
| 지도와 같이 보는 지속 정보 | `MapSupportingPanel` | 지도와 패널은 별개의 스크롤 영역이다. 폰에서 뒤로 가기는 먼저 확장된 시트를 접고, 다음 뒤로 가기는 편집 종료를 요청한다. 옆 패널은 지속 표시한다. |
| 한 값의 선택·짧은 편집 | `TaskSheet`, `MeasurementField` | 확장 모달 시트 하나만 표시한다. 바깥 탭·아래로 스와이프·뒤로·취소는 모두 같은 취소 경로다. 적용 버튼을 누른 경우에만 호출자 값을 갱신한다. |
| 여러 필드/구간의 긴 편집 | 기존 편집 화면 + `GuardDraftExit` | 화면을 벗어나기 전에 변경 버리기를 확인한다. 확인창의 뒤로·바깥 탭·계속 편집은 초안을 유지한다. 계획은 원본과 별도 초안으로 편집하고 저장 중에는 이탈을 막는다. |
| 삭제 | `AlertDialog` | 되돌릴 수 없는 삭제에만 명시적 확인을 유지한다. |

입력 모달은 부모의 다른 컨트롤을 차단한다. 호출자는 하나의 시트에서 새 모달/확인창을 열지 않는다. 다른 일시 작업을 열려면 현재 시트를 먼저 닫는다. `TaskSheet`는 화면상 숫자 패드 입력을 위해 본문을 스크롤하고 확인/취소 액션을 별도 하단 영역에 둔다. 시스템 뒤로 가기는 먼저 IME를 닫고, 다음 뒤로에서 모달을 취소할 수 있다.

## 거리·운동 시간·페이스

`MeasurementField(label, kind, value, onConfirm, minimumMeters, onClear)`의 `value` / `onConfirm`은 거리 **m**, 운동 시간 **s**, 페이스 **s/km**다. `MeasurementKind.DURATION`은 경과 시간이며 자정/오전·오후 개념이 없다. 시계 시각(시:분)을 입력하는 기능에는 이 API를 재사용하지 않는다.

| 입력 | 단위·직접 입력 | 허용 범위 | 빠른 선택·조정 |
| --- | --- | --- | --- |
| 거리 | 입력창 오른쪽 km/m 드롭다운 + 소수 숫자. 소수점 쉼표도 수용하며 비숫자 편집/붙여넣기는 전체 거부 | 양수~200km. 시작 목표는 100m~200km | 1/5/10/20km, 하프 21.0975km, 풀 42.195km, ±100m |
| 운동 시간 | 시·분·초를 분리, 숫자 패드 | 양수~12,000초(200분), 새 입력의 해상도는 1초. 분·초 각각 0~59 | 5/10/30분, ±1분 |
| 페이스 | 분·초를 분리, 숫자 패드. 콜론 타이핑 불필요 | 120~1800초/km(2:00~30:00), 초 0~59 | 5:00/6:00/6:30/7:00, ±5초/km |

분리 숫자 입력 + 프리셋 + 증감 버튼을 선택했다. 시계 다이얼은 페이스/운동 시간을 시각으로 오해시키고, 휠만 제공하면 좁은 창·키보드·TalkBack에서 정확한 값을 입력하기 어렵다. 직접 숫자 입력을 항상 제공하며 단위·현재 후보·오류·적용 가능 여부를 즉시 표시한다. km/m 전환은 `convertDistanceText`의 BigDecimal 소수점 이동으로 초안 문자열의 정밀도와 범위 밖 물리량까지 보존한다. `distanceInputText`는 적용값(m)을 Double 나눗셈 없이 표시한다. 최종 저장은 기존 Double m 단위다.

거리 편집은 `acceptDistanceEdit`로 ASCII 숫자와 소수 구분자 하나만 수용한다. 영문·한글·단위·부호·지수·공백이 섞인 변경은 원래 초안을 유지한다. 글자만 제거해 `-1`을 `1`, `1e3`을 `13`으로 바꾸지 않는다. 빈값·단독 소수점·끝 소수점은 편집 중 상태로 허용하지만 완성된 양수 거리만 적용한다. 초기값·프리셋·단위 전환은 같은 숫자 표시 헬퍼를 사용하며 시작 목표와 계획 거리에서 같은 `DistanceEditor`를 호출한다. 문구 기준은 [UI 문구 점검](UI_COPY_AUDIT.md), 거리 조작·정확성은 [거리 입력 정책](DISTANCE_INPUT_VALIDATION.md)에 있다.

검증은 `core/MeasurementInput.kt`의 `parseDistance`, `parseElapsed`, `parsePaceParts`, 기존 문자열 호환용 `parsePace`, `MeasurementLimits`를 사용한다. `InputDraft`는 원래 값과 후보를 분리한다. 지수 표기/NaN/무한대/음수/빈 필드/60초/정수 overflow는 적용할 수 없다. 프리셋이나 미세 조정도 동일 범위를 따른다. 취소 후 재열기는 적용된 값에서 시작한다. 선택 해제는 선택형 목표에만 제공하는 명시적 적용이다.

계획 구간 추가와 저장 시 `MeasurementLimits`를 다시 검사한다. 기존 모델을 재해석하거나 이미 저장된 기록을 마이그레이션하지 않는다. 기존 소수 운동 시간은 양수·200분 상한 내에서 유지하며 새 시트 입력은 정수 초다. 코스 목표나 계산기에서 다른 도메인 범위가 필요하면 공통 범위 정책을 명시적으로 확장하고 UI와 저장 검증을 함께 변경한다.

## 접근성·여백·제스처

- Material 3 버튼/아이콘 버튼의 48dp 최소 인터랙션 영역을 유지하고 공통 프리셋·거리 단위 버튼/메뉴에는 48dp 최소 높이를 명시한다. 단위 버튼은 ‘거리 단위’와 현재 단위를 접근성 의미로 제공하고 메뉴는 선택 상태를 제공한다. 아이콘은 이름을 제공하고 탭/칩에는 Material의 선택 상태·역할을 사용한다. 장식 아이콘은 중복 낭독을 피한다.
- 시트 제목·공통 Section은 heading, 주요 수치는 병합된 의미, 입력 후보·오류는 polite live region이다. 코스 지점은 버튼 역할·선택 상태·지점 번호를 제공한다. Material 기본 핸들/바깥 닫기의 이름은 기기의 UI 언어에 따른다.
- `AdaptiveActions`는 버튼·프리셋·수치를 줄바꿈하고 `Section`의 보조 액션은 제목 아래에 둔다. 작은 창 또는 1.5배 이상 글꼴에서 분·초 입력을 세로 배치한다. 주요 버튼에는 고정 높이 대신 최소 높이를 사용한다.
- Root의 Scaffold padding을 소비한 뒤 IME inset을 적용한다. 시트는 safeDrawing과 IME inset을 처리한다. 입력/긴 목록은 스크롤하고 시스템 바 아래에 버튼을 놓지 않는다.
- 지도는 기존 `MapGestureFrame`의 native touch 경계를 유지한다. 바텀시트 핸들/목록과 지도 영역을 분리한다.

이 정책의 자동 검사 범위와 기기 확인 한계는 [검증 기록](VALIDATION.md)에서 구분한다. 실제 Fold 힌지, TalkBack 음성 탐색, native 카카오 지도 인증·제스처를 에뮬레이터 preview 결과로 통과 처리하지 않는다.

## 화면별 흐름

- 달리기는 지도·접히는 진행 패널과 고정 시작/일시정지/재개/종료 영역으로 나눈다. 시작 전 코스·계획 선택은 적용/취소가 있는 시트, 거리·페이스는 공통 입력을 사용한다. 측정과 권한 요청은 기존 서비스에 맡긴다.
- 코스는 선택 지점 요약·이전/다음·삽입·삭제·선택 해제를 드로워에 모으고 파일 작업을 더보기 시트에 둔다. undo, native 마커 드래그, 지점 제한과 저장 이름 초안을 유지한다.
- 계획은 저장 목록과 별도 편집 초안을 사용한다. 기존 구간을 누르면 입력이 펼쳐지고 목록 하단에서 추가한다. 48dp 핸들을 길게 눌러 드래그하며 가장자리에서 자동 스크롤한다. 접근성 custom action으로도 순서를 바꾼다. 안정된 편집용 ID는 저장 포맷에 넣지 않는다. 취소·drag 취소·실행 취소와 저장 실패는 원본을 보존한다. 총거리·예상 시간·거리 가중 평균 및 100구간/20회 반복 제한을 유지한다.
- 기록은 요약·구간·그래프·심박수를 선택하고 지도를 확대하면 구간 패널을 함께 표시한다. 목표/전체 범위를 통계·트랙·구간·심박수에 동일하게 적용한다. 전체 보기의 표시용 사본에서 목표 경계를 해제하며 원본과 JSON은 전체를 보존한다. GPX는 파일 저장을 요청한 범위를 유지한다. Health 후보는 스크롤 가능한 선택 시트로 표시하며 읽기 실패·권한·빈 결과·재시도를 구분한다. 빈 결과의 원인을 UI에서 단정하거나 Health 원본 필터를 바꾸지 않는다.
- 설정은 페이스/길 안내, 음성/경보, 측정/위치, 개인/화면, 데이터/권한으로 나눈다. GPS 시나리오 편집기는 simulation 빌드의 별도 진입으로 유지한다. 위치 테스트의 지도는 새로 수신한 실제 위치만 표시하고 정확도와 권한/수신 상태를 함께 제공한다. preview는 명시적 지도 대체 상태다.
- 음성 샘플은 같은 버튼에서 재생/중지를 처리한다. 완료는 버튼 상태를 복구하고 오류·명시적 중지·화면 이탈은 자동 재생 문맥을 해제한다. 사용자가 먼저 시작한 샘플에만 관련 설정 변경 후 450ms debounce를 적용한다. 미종료 운동 중에는 테스트를 막아 서비스 안내와 충돌하지 않는다. SpeechPlayer와 실제 운동 음성/경보 정책은 변경하지 않는다.

`MapSupportingPanel`의 선택적 `peekHeight`는 호출자가 요약·선택 조작 높이를 반영한다. 반환 여백은 시트의 실제 offset을 사용하며 초기 미측정 상태에서는 peek를 사용한다. 호출자는 지도에 이 여백을 적용하여 native 카메라와 컨트롤의 가림을 피한다. 폰에서는 지도 공간을 남기고, 모든 지도에서 카메라 버튼을 같은 48dp 아이콘/접근성 이름/따라가기 상태로 표시한다. 경로·위치 없음과 preview 미지원에서는 비활성으로 표시하고 실제 위치 점만 유지한다. 구간 표도 좁은 창/큰 글씨에서 이름이 있는 행 카드로 표시한다. `GuardDraftExit`의 선택적 `enabled=false`는 저장 중 이탈 요청을 막는다.

## 오디오 옵션 확장

기존 음성/경보/케이던스 범주 안에서 앱 전체 음성, 목표 이탈 음성 전체와 상태/현재/목표 독립 선택, 거리 현재 안내, 1km 누적 평균, 경보와 지속 메트로놈을 구분한다. 페이스 전체가 꺼지면 하위 선택/반복 컨트롤을 비활성화하되 값을 보존한다. 거리 현재 간격은 별도 적용/취소 시트에서 정수 10~10000m와 10/20/100/200/1000m 프리셋을 사용한다. 공통 MeasurementField/DistanceEditor와 계획 입력은 변경하지 않는다.

목표 케이던스와 측정값을 구분하고 기존 입력 정책 120~220spm·기본 180을 추천값으로 표시하지 않는다. 목표/180/185 메트로놈을 약 1초 미리 듣고 완료·실패·중지·화면 이탈·미종료 운동에서 정지한다. 페이스 예문은 현재 선택만 반영한다. 모든 선택이 꺼지면 재생 버튼을 비활성화하며, 사용자가 시작했던 샘플에만 관련 선택/음량/목표 변경의 450ms debounce를 적용한다.

## 코스·기록 후속 정리

저장 코스는 최초 전체 경로를 맞춘 뒤 지점 선택·지도 이동·경로 수정으로 카메라를 다시 초기화하지 않는다. 선택 패널은 번호/필요한 거리/이전·다음·삽입·삭제·해제 조작만 남기고 첫 지점의 0km를 생략한다. 저장 코스 목록 삭제는 이름 확인·취소·진행 잠금·실패 재시도와 기존 목록 Flow를 사용한다.

심박수 기본 빈 상태는 가져오기 버튼 하나로 표시하며 권한·진행·실제 빈 조회·실패/재시도·완료를 구분한다. 코스/기록 더보기의 내보내기 하나에서 `ExportSelectionSheet`를 열고 지원 형식/범위를 선택한다. `rememberFileExporter`는 선택한 내용 사본과 GPX/JSON MIME, 시스템 선택/쓰기 중 잠금·취소·실패·완료를 공통으로 관리한다. 데이터 없는 GPX는 비활성이고 JSON은 전체 기록/심박수를 보존한다.
