# 달리기 준비 화면

## 원인과 변경

준비 화면은 시작 전의 선택과 운동 중 측정 정보를 분리한다. 화면 구성은 소스의 정책이며 현재 휴대폰에서 직접 실행한 검증 결과는 아니다.

시작 전에는 별도의 스크롤 화면에서 코스·페이스 계획·목표와 출발 대기/음성 요약을 표시한다. 코스 목표 편집은 요약 행에서 펼친다. 실제 종료 기록이 있을 때만 최근 거리·시간·페이스 행과 상세 진입을 표시한다. 상단의 배경 없는 +와 톱니바퀴는 48dp 조작 영역과 접근성 이름을 갖는다. Root는 저장 기록의 최신 FINISHED 운동과 설정 진입을 전달한다.

코스·계획·편집 구간은 `SelectionRow`와 `DomainSelectionSheet`를 재사용한다. 없음/페이스만, 안정된 ID별 단일 radio 선택과 적용/취소를 제공하며 8개 이상 공통 목록에서는 검색할 수 있다. 시트 밖에서 `DomainSelectionState`의 검색어와 `LazyListState`를 함께 보관하여 닫기/취소 후 재진입에도 검색 결과와 위치를 유지한다. 공통 시트는 독립 `LazyColumn`에서 안정 key로 보이는 행만 구성하고 `TaskSheet(scrollable = false)`를 사용하므로 같은 방향 스크롤을 중첩하지 않는다. 최대 10,000지점 코스의 9,999개 편집 구간도 이 목록 경로를 사용한다. 미적용 후보는 호출자의 코스·계획에 쓰지 않는다. 목표 거리·페이스는 기존 정확한 단위의 한 값 입력을 사용한다.

코스 이름의 `%`, `%s`, `%n`을 형식 문자열로 해석하지 않고 그대로 표시한다. 거리 숫자만 따로 포맷하며 코스 선택 요약은 목록이 변경될 때 계산한다.

## 보존 계약

- `RunPreparationSelection`은 기존 시작 사본 계산을 추출한다. 코스만/페이스만/함께, 안정된 지점 목표 연결과 실제 통과/계획 거리 전환, 미설정 구간, 혼합/시간 계획의 예상 거리와 거리 목표 구분을 유지한다.
- 목표 거리·일정 페이스 초안은 다른 모드에서 숨겨도 보관한다. 코스 목표 편집은 운동 시작 사본에만 반영하고 저장된 원본 코스를 변경하지 않는다.
- 권한 요청은 Root의 시작 경로를 유지한다. 정확한 위치 권한·휴대폰 위치 기능이 실제 시작을 막으면 기존 Root snackbar/서비스 오류를 표시한다. 준비 화면의 일반 GPS 수신/오차 문구를 별도 시작 조건으로 해석하지 않는다. 자세한 위치 확인은 설정의 기존 진입을 사용한다.
- 출발 대기 중 초 표시·뒤로/취소의 요청 ID, 시작/일시정지/재개/종료의 운동 ID와 명령을 유지한다. 운동 진행 중 지도·카메라 따라가기·진행 패널·구간 표·종료 확인을 유지한다. 측정·음성·서비스·DB 정책은 변경하지 않는다.

## 검증과 한계

[RunPreparationSelectionTest](../app/src/testSimulation/java/com/runkeep/app/ui/RunPreparationSelectionTest.kt)는 준비 선택의 순수 정책을 검사한다. 이는 Compose UI 실행 검사가 아니다. 무계획 시작, 21097.5m·397초/km 보존, 저장 계획 우선/시간 계획의 비고정 거리, 코스 목표/미설정 구간/전환 방식 사본, 코스만 전환의 목표값 보관, 입력 범위와 짧은 코스 정책, 퍼센트/포맷 문자가 포함된 이름의 문자 그대로 표시를 검사한다.

자동 검사 설정·범위와 공개 CI 상태는 [검증 기록](VALIDATION.md)에 정리한다. GitHub Actions는 JDK 25 / JVM 21 / JUnit 5에서 core·simulation 단위 테스트와 preview/kakao debug·simulation 네 variant 빌드·lint를 수행하도록 설정되어 있다.

실제 터치, 긴 목록 검색/취소/재진입, 큰 글꼴·TalkBack, 야외 GPS·지도 인증·음성 청취는 실행하지 않았고 소스/자동 검사와 구분한다.
