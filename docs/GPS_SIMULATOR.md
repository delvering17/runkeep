# 앉아서 GPS 기능 테스트하기

## 내 시나리오 만들기

설정 → GPS 시뮬레이터 → **새 시나리오**에서 이름과 **목표 페이스**를 지정한다. 구간을 눌러 지속 시간과 **입력 페이스**를 분·초 숫자로 설정한다. 예: 목표 6:05/km, 30초 6:05/km → 15초 정지 → 60초 5:00/km. 콜론을 직접 입력할 필요 없다.

- **구간 추가**, 드래그 순서 변경, 삭제를 지원한다. 왼쪽 핸들을 길게 누른 뒤 움직이고, 화면 가장자리에서 계속 끌면 목록이 자동으로 스크롤된다. TalkBack은 구간의 이동 액션을 사용한다. 구간 추가는 바로 입력 화면을 연다. 구간 입력의 **적용**은 편집 중인 초안만 바꾸고, 시나리오 **저장**을 눌러야 앱에 보관한다. 취소·뒤로·바깥 닫기는 저장값을 바꾸지 않고 확인 없이 초안을 버린다. 구간 입력의 취소는 그 입력만 버리고 목록으로 돌아간다. 시스템 뒤로는 시나리오 편집 전체를 닫는다. 원래 코스·페이스 계획 편집의 정책은 바꾸지 않는다.
- 달리기·정지·GPS 미수신·정확도 저하를 선택한다. 정지는 기본적으로 정확한 제자리 위치와 속도 0이며 **GPS 흔들림**을 켜면 2m 흔들림과 간헐적 속도 오류를 생성한다. 정확도 저하는 60m 오차다. 미수신/정확도 저하 중 가상 위치는 입력 페이스로 계속 이동한다.
- **목표 페이스**는 빠름/느림을 비교할 기준이고, **입력 페이스**는 해당 구간의 가상 GPS 이동 속도다. 목표를 구간마다 자동 변경하지 않는다.
- 시나리오는 최대 20개, 시나리오마다 1~30구간, 구간 1초 이상·전체 최대 200분, 목표/입력 페이스 2:00~30:00/km다. 시간·페이스의 초는 0~59이며 빈 값·범위 밖 값은 적용/저장하지 못한다.
- 저장하면 해당 시나리오가 선택된다. 선택 목록의 **내 시나리오**에서 다시 고르거나 **편집**으로 수정한다. 앱을 다시 켜거나 같은 앱 ID와 서명을 사용한 테스트 빌드로 업데이트해도 보관한다. 테스트 앱을 삭제하거나 앱 데이터를 지우면 사라진다.
- 저장한 시나리오·선택은 테스트 앱 전용 저장소를 사용한다. 잘못된 저장 내용을 읽었을 때 원본을 자동으로 덮어쓰지 않으며, 명시적 초기화만 허용한다. 운동 기록 DB를 변경하지 않는다.
- 운동 실행 중에는 시나리오 선택·편집·삭제를 막는다. 실행 시 설정을 고정하므로 저장 내용을 바꿔서 진행 중인 입력이 갑자기 달라지지 않는다.

실시간 1배속이다. 현재 페이스는 최근 20초 창·최소 8초/8m, 페이스 음성은 범위 밖 상태 10초 지속 후 동작한다. 몇 초짜리 변속은 입력되더라도 음성까지 나오지 않을 수 있으므로 음성 검증 구간은 40초 이상을 권장한다. 자동 정지 검증은 정지 구간을 8초보다 길게 두며 GPS 오류를 켜면 더 늦어질 수 있다. 재생이 끝나면 직접 **테스트 종료**를 누른다.

## 설치와 시작

GPS 시뮬레이터는 `simulation` 빌드에만 포함된다. 일반 `debug`와 `release`에는 좌표 생성기·재생 화면이 포함되지 않는다. Android의 모의 위치 앱 설정은 필요 없다. 다른 앱의 GPS를 바꾸지 않는다.

1. 최신 `main`을 Pull하고 프로젝트를 Android Studio에서 연다. Build Variants에서 `kakaoSimulation` 또는 `previewSimulation`을 선택한다.
2. 휴대폰에 실행한다. 앱 이름은 **런킵 GPS 테스트**이며 기존 런킵과 나란히 설치된다. 기존 앱을 삭제할 필요 없다.
3. 설정 맨 위 **GPS 시뮬레이터**에서 시나리오를 고른다. 음성·자동 일시정지·페이스 허용 범위를 필요에 맞게 설정한다. 페이스 경보음도 켤 수 있다.
4. **테스트 시작**을 누르고 정확한 위치·알림 권한을 허용한다. 실제 위치 대신 고정된 테스트 경로가 기록 서비스에 들어간다. 목표는 6분 5초/km다.
5. **달리기** 탭에서 지도·페이스·거리·구간 표·안내를 확인한다. 설정으로 돌아와도 재생이 이어진다.
6. 설정의 **테스트 종료** 또는 달리기 화면의 **종료**로 기록을 저장하고 끝낸다. 다음 시나리오는 기존 운동을 종료한 뒤 시작한다.

`GPS 입력 쉬기`는 위치 입력만 멈추며 운동 시간을 정지하지 않는다. 수동 운동 정지·재개는 달리기 화면의 버튼으로 확인한다. 시나리오 재생 완료도 운동을 자동 종료하지 않는다. GPS 미수신 후의 동작을 관찰한 다음 직접 종료한다. 시작 버튼을 다시 누르면 첫 지점부터 새 운동으로 재생된다.

현재는 **실시간 1배속**이다. GPS 타임스탬프·서비스 타이머·음성 간격이 실제 시간과 맞아야 하므로 좌표만 배속하여 페이스 결과를 왜곡하지 않는다. 케이던스 센서와 심박수는 생성하지 않는다. 시뮬레이터 선택·진행 상태는 프로세스 종료 시 초기화되므로 중단된 테스트 기록은 달리기 탭에서 종료한 뒤 새 테스트를 시작한다.

## 별도 앱 ID와 지도

- `kakaoSimulation`: `com.runkeep.app.gpstest`
- `previewSimulation`: `com.runkeep.app.preview.gpstest` (지도 대신 경로 도식)
- 같은 앱 ID와 서명을 사용하는 simulation 빌드로 업데이트할 때 테스트 DB를 유지한다. 서명이 다른 빌드는 기존 앱에 덮어 설치할 수 없다. 업데이트 전에 진행 중인 테스트 운동을 종료한다.
- 카카오 실제 지도를 보려면 카카오 개발자 콘솔의 Android 플랫폼에 **`com.runkeep.app.gpstest`**도 등록하고 해당 빌드에 사용하는 서명 키의 키 해시를 등록한다. 이 설정은 앱이 자동으로 변경하지 않는다. 기존 런킵 패키지 등록은 유지한다.
- 테스트 데이터는 별도 앱 DB에만 저장된다. Health Connect·내보내기는 별도 요청하지 않는 한 사용하지 않는다. 시뮬레이터 경로는 사용자의 실측 경로가 아니다.

## 시나리오와 판정

| 시나리오 | 시간 | 확인할 결과 |
| --- | --- | --- |
| 제자리 GPS 흔들림 | 90초 | 2m 좌표 흔들림과 간헐적 속도 오류에도 자동 정지 후 재개가 반복되지 않는다. |
| 달리기 → 정지 → 재개 | 120초 | 40초 달린 뒤 30초 멈췄다가 다시 이동하면 자동 재개된다. 정지 구간과 재개 연결 거리를 더하지 않는다. |
| 정상 → 느림 → 빠름 → 정상 | 250초 | 20초 추정 창이 변화를 반영한 뒤 느림/빠름 안내가 나온다. 정상 복귀 시 경보가 멈춘다. 음성 간격과 선택 읽기를 확인한다. |
| GPS 끊김 · 정확도 저하 | 127초 | 22초 미수신과 30초 오차 60m 동안 허위 거리·페이스가 생기지 않고 정상 수신 시 회복된다. |
| 1km 음성 · 지점 통과 | 440초 | 약 1.2km 이동, 회전·구간 표·1km 안내. 평균 페이스가 ‘6분 5초’로 읽힌다. |

시뮬레이터는 합성 위치를 기록 서비스에 전달한다. 시나리오 결과를 기록할 때 앱의 브랜치·커밋과 사용한 설정을 함께 남긴다. 합성 입력의 동작이 실제 GPS·오디오 출력의 성공을 보증하지 않는다.

## 빌드와 자동 검사

```sh
./gradlew :core:test :app:testPreviewSimulationUnitTest
./gradlew :app:assembleKakaoSimulation :app:lintKakaoSimulation
./gradlew :app:assemblePreviewSimulation :app:lintPreviewSimulation
```

APK는 `app/build/outputs/apk/kakao/simulation/`, `app/build/outputs/apk/preview/simulation/`에 생성된다. `-PgpsTestLabel='자동 정지 검증'` 등으로 설정 화면에 테스트 대상을 표시할 수 있다. 시나리오의 순서·속도/좌표 일치·GPS 공백/정확도·1km 경계·RunEngine 계산을 JUnit 5로 검사한다. 순수 로직 검사와 실제 기기 또는 에뮬레이터에서 수행한 동작 검증은 [검증 기록](VALIDATION.md)에 구분해서 남긴다.

실제 GPS 수신 잡음, 야외 거리 정확도, 기기 절전 정책, 이어폰·통화 오디오 출력은 별도 휴대폰 검증 대상이다.
