# 기록 탐색·구간·그래프·심박 가져오기

기록 UI의 표시 정책이다. 수집·GPS/페이스 엔진·Health Connect 조회/출처/중복 제거·Room 저장·원본 JSON/GPX 계산을 변경하지 않는다. 실제 기기의 터치·렌더링 검증과 소스의 표시 정책은 구분한다.

## 목록과 달력

- 주와 월은 기간 단위, 리스트와 달력은 별도 보기 방식이다. 보기 아이콘에서 두 후보를 선택하고 적용해야 함께 반영된다. 취소·뒤로·바깥 닫기는 현재값을 유지한다. 정렬·필터도 같은 적용/취소 계약이다.
- 현재 기기 시간대의 **기록 시작 시각**으로 날짜를 정한다. 주는 월요일 00:00부터 다음 월요일 00:00 전까지, 월은 1일 00:00부터 다음 달 1일 00:00 전까지다. 시간대/DST를 고려한 각 날짜의 실제 epoch 경계를 사용한다. 월 경계 주도 7일 전체를 보여주고 연말의 다음 해 날짜를 포함한다.
- 화살표는 선택 주/월을 한 단위 이동한다. 월 이동은 없는 날짜를 해당 달 마지막 날로 조정한다. 기간·보기 변경 때 달력의 선택일은 해제한다. 달력에서 같은 날짜를 다시 누르거나 `기간 전체 보기`를 누르면 날짜 제한을 해제한다. 폭이 7개의 48dp 영역보다 좁거나 큰 글꼴이면 각 주를 4일/3일 두 행으로 나누고 요일을 날짜 안에 표시한다. 날짜에는 기록 횟수를 문자로 표시하고 접근성 이름에 날짜·횟수·선택 상태를 제공한다.
- 기간 합계와 달력 날짜별 횟수는 정렬·코스·심박 필터를 적용한 같은 기록 집합이다. 선택일은 그 집합의 부분집합이다. 날짜/거리/평균 페이스 각각 양방향 정렬을 지원하며 페이스를 계산할 수 없는 기록은 양방향 모두 마지막이다. 동률은 시작 시각·ID로 결정한다.
- 코스 선택은 이름이 같은 코스를 구분하는 저장 ID를 사용한다. 코스 없음에는 이름을 채우지 않는다. 심박 유무는 실제 Room 저장 심박 run ID 집합으로 판정한다. 목표 달성 기록의 거리·시간 합산은 종전 목표 기준을 유지하며 목록의 반복 목표/추가거리 설명과 최고 페이스 카드는 제거한다.
- 필터 시트는 코스·심박 헤더와 각 선택 행을 단일 LazyColumn item으로 가상화한다. TaskSheet 바깥 스크롤을 사용하지 않는다. 검색어와 목록 위치는 시트 조건 밖의 DomainSelectionState에 보관해 재진입 때 유지하고, 선택 후보는 적용 때만 현재 필터에 반영한다.
- 기간·보기·정렬·필터·선택일은 `rememberSaveable`, 목록 위치는 `rememberLazyListState`로 Root의 화면 상태 보관 계약 안에서 복원한다. 상세에서 목록으로 돌아가도 탐색 상태를 재설정하지 않는다.

## 상세와 구간

- 상세는 요약→지도→실제 보조 수치→짧은 1km 구간 미리보기→그래프→심박 가져오기 순서의 주 LazyColumn이다. 카드 중첩과 네 개의 동일한 섹션 선택 버튼을 제거한다. 지도 확대와 전체 구간 진입은 짧은 명명 조작이다. 가져오기 상태는 해당 조작 옆에서만 표시한다.
- 전체 구간은 같은 상세 내부의 독립 페이지이며 헤더와 각 구간 행을 별도 item으로 둔 하나의 주 LazyColumn만 사용한다. 9,999개 코스 구간도 전체 Compose 행을 한꺼번에 구성하지 않는다. inline `PaceTable`은 스크롤을 소유하지 않는 콘텐츠다. 320dp 내부 viewport를 제거했다. 확대 지도 패널에서는 3구간만 미리 보여준다.
- 1km/코스 지점별, 실제 지점 통과/누적 거리 계산은 기존 `PaceProgress`를 그대로 사용한다. 코스 계산 기준은 기존처럼 미선택에서 시작하며 실제 통과/누적 거리 중 명시적으로 적용해야 구간을 표시한다. 각 행에서 거리·운동 시간·페이스·상태를 명명하며 아직 실제 거리가 없는 행만 예정 거리를 표시한다. 작은 창에 가로 표를 강요하지 않는다.
- 목표/전체 표시 선택은 기록 사본·GPS·구간·심박에 기존 `RecordPresentation`을 일관되게 적용한다. 상세/구간/지도 사이의 뒤로 가기는 먼저 해당 하위 화면을 닫고 상세 스크롤을 보존한다. 독립 구간 선택 상태와 LazyListState도 상세 수준에서 보관해 재진입 때 유지한다. JSON은 전체 원본, GPX는 내보내기 시트에서 고른 전체/목표 범위를 유지한다.

## 표시용 그래프

- x축 시간은 **시작 후 wall-clock 경과 시간**이며 일시정지 시간을 포함한다. 운동 시간(`activeMs`)과 구분한다. Health epoch 시각은 같은 epoch GPS와 비교하므로 시간대 표시 변환으로 거리를 추정하지 않는다.
- y축은 심박 bpm, 페이스 분:초/km, 측정 케이던스 spm, GPS 고도 m이다. 페이스는 작은 값(빠름)이 위쪽, 나머지는 큰 값이 위쪽이다. 4개 y눈금과 시작/중간/끝 x눈금, 숫자 최소/최대, 탭으로 고른 정확한 표본 값과 경과/거리를 제공한다. 접근성 이전/다음 표본 액션과 선택값 live region을 제공한다.
- 거리 매핑은 유효 GPS 표본과 정확히 시각이 같거나 같은 segment의 인접 표본 사이에서만 한다. 인접 epoch 간격은 15초 이하, 운동 시간은 증가하며 epoch 간격보다 1초를 초과해 길지 않아야 하고, 거리는 비감소여야 한다. 저장 지점의 거리/시간/정확도 값도 유효해야 한다(정확도 0~25m). GPS 시작 전/끝 후, segment 변경/정지/긴 공백을 넘는 보간은 하지 않는다. 일부만 매핑되면 확인 개수/전체 개수를 표시하며, 근거가 전혀 없으면 시간 축으로 유지한다.
- GPS interval의 segment 변경/15초 초과/운동 시간 비증가·시계 불일치/거리 역행·불량 정확도, 표본 segment 변경·값 없음/비유한·샘플 간 긴 공백은 연결선을 끊는다. GPS 기반 그래프의 샘플 공백 한도는 15초, 심박은 30초다. GPS가 전혀 없는 심박은 시각 자료 자체를 시간 축으로 읽을 수 있다. 고도/케이던스 없는 표본을 건너뛰어 앞뒤를 연결하지 않는다.
- 각 연속 구간은 최대 240점으로 시각화용 축약한다. 원래 순서와 처음/끝, 각 버킷의 최소/최대를 보존한다. 축약한 점의 선택값도 실제 원본 표본 값이다. 단일 표본은 숫자와 점을 표시한다. 원본과 내보내기 자료를 바꾸지 않는다.

## 심박 작업 생명주기

- 실제 후보/권한 확인, 플랫폼 권한 요청, 심박 읽기, Room 저장, 진단 동안 진행 표시와 중복 잠금을 유지한다. 가짜 지연을 추가하지 않는다. 완료·빈 조회·권한 거부·읽기/저장 실패는 종료 상태이며 기존 원인별 재시도 안내를 사용한다.
- 가져오기·취소 조작은 줄바꿈 가능한 AdaptiveActions에 두고 각각 최소 48dp 높이를 유지한다. 진행 표시는 가져오기 버튼 안에 포함해 큰 글꼴·좁은 폭의 고정 Row에서 취소가 밀리는 구성 위험을 줄인다. 실제 렌더 재현은 미실행이다.
- 운동 후보 시트도 설명·검색·각 후보·런킵 시간대 선택을 하나의 LazyColumn에 두며 각 운동의 실제 session ID를 stable key로 사용한다. 검색 전에 원본 인덱스를 유지하므로 검색 후 선택·적용도 원래 candidates의 같은 운동을 가리킨다. Health Connect 후보 조회·정렬·중복 제거는 그대로이며, 시트 밖에 둔 검색어·목록 위치만 재진입 때 보관한다.
- 요청은 화면 인스턴스 소유 토큰으로 검사한다. 취소·화면 이탈은 토큰을 무효화하고 Job을 취소한다. 같은 기록 ID로 다시 들어와도 이전 권한/조회/읽기/저장 콜백은 새 화면을 갱신하지 않는다. 성공한 심박은 기존 DAO Flow로 그래프/평균/최대에 반영된다.
- 후보/심박 읽기·진단은 취소할 수 있다. 플랫폼 권한 절차는 시스템 UI에서 허용/거부한다. 결과가 대기 중이면 같은 launcher의 새 요청을 막는다. 저장이 시작되면 명시적 취소와 앱 내 화면 이탈을 막는다. 강제 composition 제거에서는 작업을 취소하며, 이미 커밋된 저장은 원래 run ID에 남을 수 있다. 다른 기록 ID로 저장하지 않는다. Room `@Upsert`와 기존 저장 정책은 변경하지 않는다.

## 검증 상태

기록 목록의 순수 정책 회귀는 월/연말/윤년/DST·반열린 경계·정렬/없는 페이스·같은 코스명/다른 ID·저장 심박·선택일·목표 표시 원본 보존을 검사한다. 차트 회귀는 epoch 보간/부분 겹침·정지/segment/미수신/시간 의미·단일/빈/비유한·중복/역순·장시간 극값 축약과 원본 보존을 검사한다. 앱 단위 회귀는 요청 중복·권한 후 계속·취소 후 늦은 결과·화면 재진입 소유권·오래된 완료의 잠금 해제 금지를 검사한다.

자동 검사 설정·범위와 공개 CI 상태는 [검증 기록](VALIDATION.md)에 정리한다. GitHub Actions는 JDK 25 / JVM 21 / JUnit 5에서 core·simulation 단위 테스트와 preview/kakao debug·simulation 네 variant 빌드·lint를 수행하도록 설정되어 있다.

큰 글꼴 실제 배치·터치·TalkBack 낭독·Health Connect/Room/시스템 권한 UI 실행 검증은 미실행이다. 코드/정책/CI 검증과 실제 실행 검증을 구분한다.
