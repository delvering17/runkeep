# 코스·페이스 통합

## 설정과 재사용

코스·페이스 탭의 페이스만은 기존 거리/시간 계획 편집기, 코스만과 코스·페이스는 기존 지도/지점 드로어 편집기를 연다. 코스 편집에서 두 모드를 전환하며 저장 계획의 목표를 가져올 수 있다. 기존 계획을 수정하거나 코스를 복제해야 사용할 수 있는 구조가 아니다.

출발 화면에서 코스 없이 계획을 고르면 기존 거리/시간 엔진을 사용한다. 코스만 고르면 독립 코스를 사용하며, 코스에 저장된 지점별 목표를 켜거나 끌 수 있다. 코스와 계획을 함께 고르면 계획의 1번 목표를 1→2, 2번 목표를 2→3에 순서대로 연결한 운동용 초안을 만든다. 계획의 거리/시간은 이 연결에 사용하지 않으며 실제 코스 선분 길이로 예상 시간을 계산한다. 부족한 목표는 미설정, 초과 목표는 적용하지 않는다. 원본 계획은 바뀌지 않는다. 출발 화면의 구간별 변경은 해당 운동 사본이고, 재사용할 변경은 코스 편집에서 저장한다.

지도 선분/마커와 목록에서 같은 구간을 선택하며 번호·직선 거리·목표를 표시하고 선택 선분을 강조한다. 페이스 숫자/분·초는 공통 MeasurementField, 계산은 기존 PaceCalculatorInputs/정확한 계산 정책, 지점 순서 변경은 계획 편집기에서 추출한 RowReorder를 사용한다. 길게 누른 핸들의 가장자리 자동 스크롤, 접근성 위/아래 이동, 드래그 취소와 실행 취소를 보존한다. 새 의존성이나 UI 전면 교체는 없다.

## 지점과 목표 식별

Coordinate와 points 배열 형식은 그대로다. Course.pointIds는 points와 같은 길이의 고유 ID이며 CoursePaceTarget은 fromPointId/toPointId/paceSeconds를 저장한다. 지점별 좌표가 같아도 ID가 달라 짧은 왕복·시작/끝 겹침이 구분된다. 기존 ID 없는 코스는 코스 ID와 원래 순서에서 결정적으로 생성하여 반복 디코딩에서 동일한 ID를 얻는다. 새 지점은 UUID를 한 번 생성하고 초안/저장/교환 파일에서 유지한다.

| 편집 | 연결 정책 |
| --- | --- |
| 좌표 이동 | ID와 인접 관계를 유지하며 거리·예상 시간 재계산 |
| 지점 삽입 | 분리된 이전 연결 제거, 두 새 연결은 미설정 |
| 지점 삭제 | 삭제 지점의 연결 제거, 합쳐진 새 연결은 미설정 |
| 순서 변경 | 최종 순서에서 여전히 인접한 같은 방향의 ID 쌍만 보존. 드래그의 임시 순서는 연결을 영구 삭제하지 않음 |
| 되돌리기/드래그 취소 | 좌표·ID·목표·전환 정책을 함께 복구 |

한 방향의 인접 쌍에는 목표 하나만 저장하고 중복·비인접 연결·잘못된 ID/페이스는 거부한다. 여러 구간을 하나의 지속 범위 객체로 묶지 않는다. 전체 동일 목표 적용이나 각 구간에 같은 목표를 적용하면 각 인접 쌍에 저장한다. 재적용은 그 쌍의 목표를 교체하여 겹치는 범위의 우선순위가 생기지 않는다.

usePaceTargets를 끄면 목표 자료를 보관하면서 코스만 사용할 수 있다. 미설정은 이전 목표를 물려받지 않고 코칭·경보를 쉬는 구간이다. 0.01m 이하인 중복 좌표 연결은 예상 시간 0이며 진행 확인 후 통과 처리한다. 유효 길이 없는 코스의 지점별 페이스 운동은 시작하지 않는다.

## 운동 전환

코스에 paceTransition을 저장하고 운동은 coursePaceEnabled로 엔진 종류를 명시한다. 기록 표의 지점 통과/누적 거리 선택은 통계 표시만 바꾸며 이 설정을 바꾸지 않는다. 기존 운동은 coursePaceEnabled 기본 false이므로 당시 독립 계획을 그대로 사용한다.

실제 지점 통과가 기본이다. 시작 지점에 들어오거나 연속 이동으로 시작 지점을 지나기 전 목표는 없다. OrderedWaypointTracker는 다음 지점만 순서대로 검사한다. 정확도 25m 이하, 같은 기록 segment의 15초 이내 연속 위치와 증가한 운동 거리/시간을 요구한다. 다음 지점이 실제 이동 선분의 0~1 투영 범위 안에 있고, 정확도에 따른 8~20m 허용 범위 안에 있으며, 들어오는 코스 선분 방향으로 진행해야 통과한다. 단순히 가까운 원 안에 들어왔다는 이유로 5m 왕복의 다음 지점을 통과시키지 않는다. 이전 위치가 해당 코스 선분에서 35m 넘게 벗어났으면 통과시키지 않는다. 한 정상 이동이 여러 가까운 지점을 실제로 지나면 순서대로 통과할 수 있다.

계획 누적 거리는 코스 위에서 인정한 유효 실측 이동 거리를 각 코스 선분 길이와 비교한다. 전체 운동 거리와 별도 courseProgressMeters에 저장한다. CourseDistanceTracker는 이전 경로 위치에서 실제 이동량+35m 범위의 후보만 허용하고 경로 35m 이내의 연결된 전진 이동만 누적한다. 겹치는 뒤 구간을 선택하려면 중간 경계를 실제 이동 선분으로 순서대로 지나야 하며, 이미 진행한 범위는 새 이동량에서 제외한다. 역방향/왕복 잡음이 이미 진행한 경로 위치를 반복해 거리를 더하지 않도록 courseRouteMeters 최고 진행 위치를 저장한다. 경로 이탈·일시정지·GPS 공백의 이동은 전체 기록에 남을 수 있어도 계획 진행으로 몰아 더하지 않는다. 크게 건너뛰고 코스 후반에 합류하면 자동으로 후반 목표에 맞추지 않는 보수적 정책이다. GPS 공백에서 놓친 거리/통과는 추정하지 않으므로 복귀 후 목표가 실제 위치보다 늦게 유지될 수 있다.

위치 불량·단절·복구·재개는 통과 선분을 끊는다. 저장된 track points로 실제 통과 상태를 복구하고 저장한 거리 진행도도 유지하며 첫 복귀 위치를 이전 위치와 연결하지 않는다. 타이머만으로 지점/거리 목표를 넘기지 않는다. 새 운동 출발 대기는 지점별 설정 사본을 유지하고 실제 출발 시 진행도를 초기화한다.

전환 시 RunSummary.targetPace, 현재 구간 표시, Announcement.Step, PaceFeedback의 목표를 함께 바꾼다. 같은 숫자의 다음 구간도 코칭 지속 시간을 초기화한다. 미설정은 숫자를 읽지 않고 목표 미설정을 알린다. 완료 후 기본 코칭 종료, 계속 안내 설정이면 마지막 구간의 목표만 유지한다. 마지막 구간 미설정이면 그 앞 목표로 되돌아가지 않는다. 운동 기록은 수동 종료까지 계속한다. 기존 길 안내·거리 현재/1km 음성·메트로놈·시작/종료 음성 정책을 재사용한다.

## 계산·파일·기록 호환

예상 시간은 각 양의 길이 구간에 대해 거리/1000×목표 초를 합산하고, 전체 목표 평균은 예상 시간/전체 거리×1000이다. 양의 길이의 미설정 구간이 있으면 전체 시간·평균을 표시하지 않는다. 임의 기본 페이스로 채우지 않는다. 좌표/목표/순서를 바꾸면 다시 계산한다. 구간 계산기는 결과 페이스만 선택한 ID 쌍에 적용하고 코스 좌표를 바꾸지 않는다. 계산 중 연결이 사라졌으면 적용을 막는다.

CourseFile/RunFile 내보내기는 schemaVersion 2다. 코스 JSON 가져오기는 1/2만 받는다. v1 JSON과 GPX는 기존 2MB 제한, 지점 ID/목표를 포함한 v2 JSON은 8MB 제한으로 최대 지점 수의 내보내기를 다시 읽을 수 있게 한다. 2~10,000지점, GPX 단일 segment, 좌표/ID/목표 검증은 유지한다. v1 코스·Room의 기존 코스/계획/운동 JSON은 새 필드 기본값으로 읽고 v2로 저장하면 ID가 명시된다. 구형 앱의 v1 전용 가져오기에는 v2 파일을 넣을 수 없다. GPX는 좌표 교환이며 목표와 ID를 보존하지 않는다. 운동 JSON 재가져오기 UI를 새로 만들지 않았고, 코어 판독/왕복 호환을 검증한다.

Room 테이블/컬럼/schema version 1은 변경하지 않는다. 추가 자료는 기존 Course/RunSummary JSON payload 안에 저장하므로 destructive migration이나 SQL 마이그레이션이 필요 없다. 운동 시작 요청·카운트다운·checkpoint·기록 JSON은 당시 좌표/ID/목표/전환 정책과 원본 계획 사본을 보관한다. 저장 코스/계획을 나중에 수정하거나 삭제해도 과거 기록이 바뀌지 않는다. 지점/목표 편집 초안과 이름 입력은 저장 실패/이름 대화상자 취소 뒤에도 유지한다. 명시적 변경 버리기로만 초안을 폐기한다. 큰 편집/실행 취소/출발 사본은 앱 내부 cache 파일에 보관하고 저장 상태와 서비스 Intent에는 짧은 참조만 담아 Android Binder 크기 제한을 피한다. 작은 자료와 구형 raw JSON 요청은 그대로 읽는다. 서비스가 받은 출발 사본 파일은 읽은 뒤 제거하며, 저장 상태 참조 파일이 시스템 cache 정리로 사라졌으면 저장된 원본에서 다시 시작한다. cache 사본은 사용자 내보내기 파일이나 기록 원본이 아니다.

## 검증 경계

CoursePaceModelTest/CoursePaceEngineTest와 기존 WaypointPassRegressionTest/PaceProgressTest, 기존 계획·오디오·출발/종료·GPS simulation 회귀를 함께 실행한다. 자동 빌드·단위 테스트·lint와 소스 검토의 결과는 실제 기기 동작과 구분한다. 실제 터치·카카오 지도 인증·야외 GPS·한국어 TTS/이어폰·TalkBack 청취·실기기/에뮬레이터 실행은 검증하지 않는다. 검사 대상 커밋과 결과는 [검증 기록](VALIDATION.md)에 정리한다.
