# 거리 입력 정책과 확인 범위

## 구현과 자동 검증

- 거리 입력은 제안 문자열 전체가 ASCII 숫자와 소수점(`.` 또는 `,`) 하나로만 구성될 때 수용한다. 영문·한글·혼합·부호·지수·단위 문자열·공백이 포함된 입력/붙여넣기는 원래 초안을 유지한다. `-1`을 `1`, `1e3`을 `13`으로 재해석하지 않는다.
- 빈값·단독 소수점·끝 소수점은 입력 중에 유지하고 적용을 막는다. `.1`/`,1`처럼 숫자가 완성된 소수는 `0.1`과 같은 거리로 검증한다. 거리/최소 목표/상한과 적용·취소 정책은 유지한다.
- 프리셋은 1/5/10/20km·하프(21.0975km = 21097.5m)·풀(42.195km = 42195m)이다. 현재 단위와 무관하게 같은 m 값을 설정한다.
- km/m 드롭다운은 입력창 오른쪽에 둔다. 숫자 초안의 단위 전환은 BigDecimal 자리 이동으로 처리하며 범위 밖 초안과 긴 소수를 반올림하지 않는다. 최종 저장은 기존 Double m 단위를 유지한다.
- 시작 목표와 계획 구간은 같은 `MeasurementField`의 `DistanceEditor`를 사용한다. 메뉴 버튼/항목과 프리셋은 48dp 이상 터치 영역을 유지하며 단위 버튼 이름·현재 단위·메뉴 선택 상태를 제공한다.

회귀 소스 [DistanceInputTest](../core/src/test/kotlin/com/runkeep/core/DistanceInputTest.kt)는 잘못된 직접 입력/붙여넣기, 소수/빈값, 쉼표, 긴 소수 km↔m 전환, 범위 밖 값 보존, 프리셋과 적용/취소를 검사한다. 현재 공개 CI 상태는 [검증 범위](VALIDATION.md)에 있다.

## 에뮬레이터 UI 검증

아래는 2026-10-10 당시 거리 편집과 문구 정리 단계의 preview 에뮬레이터 화면 기록이다. 360×800dp, 기본 글꼴/배율 2.0을 사용했으며 현재 공개 main의 화면 실행 결과가 아니다.

| 실제 확인한 동작 | 결과·화면 |
| --- | --- |
| 시작 목표 거리 | 여섯 프리셋이 표시되고 하프/풀은 정확한 거리와 함께 표시. [화면](screenshots/issue-28/01-distance-phone.png) |
| 오른쪽 단위 메뉴 | km/m 메뉴를 열어 하프 21.0975km↔21097.5m, 풀 42195m↔42.195km 전환 확인. 풀 적용 후 기존 입력에도 42.195km 표시. [메뉴](screenshots/issue-28/02-unit-menu.png) |
| 숫자 직접 입력·오류·취소 | 기존 숫자를 지운 뒤 `abc` 입력 시 빈 초안 유지. 200.001km는 범위 오류와 적용 비활성, IME 위에서 취소 가능. 오류값/하프 후보 취소 시 기존 풀 거리 보존. `.1` 적용 시 0.1km 표시. [IME·오류](screenshots/issue-28/03-ime-invalid.png) |
| 글꼴 배율 2.0 | 열린 시트의 하프 초안과 m 단위를 보존하고 프리셋 전체가 줄바꿈. 단위 전환과 취소/해제/적용 액션 사용 가능. [화면](screenshots/issue-28/04-distance-font2.png) |
| 페이스 계획 구간 | 같은 거리 편집기로 20km 프리셋→m 전환 시 20000 표시. 적용 후 구간 거리 20km 확인. [화면](screenshots/issue-28/05-plan-distance.png) |

한글/혼합 문자열과 실제 클립보드 붙여넣기는 UI에서 실행하지 않았으며 동일한 편집 검증 함수의 자동 테스트로 확인했다. 실제 Fold 접힘 자세·멀티윈도우·TalkBack 음성 탐색·카카오 native 지도는 이번 에뮬레이터 검증 범위 밖이다.
