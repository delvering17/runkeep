# runkeep · 런킵

[![Android build](https://github.com/delvering17/runkeep/actions/workflows/android.yml/badge.svg)](https://github.com/delvering17/runkeep/actions/workflows/android.yml)

**내가 만든 코스와 구간별 목표 페이스로 달리는 Android 러닝 앱입니다.**

휴대폰으로 거리·시간·페이스를 기록하고, 지도에 직접 만든 코스와 페이스 계획을 함께 사용할 수 있습니다. 코스나 목표 없이 자유롭게 달리는 것도 지원합니다. 운동 기록과 코스는 휴대폰에 저장하며 별도 런킵 서버를 사용하지 않습니다.

현재 개발 중인 앱이며 Android 10(API 29) 이상을 대상으로 합니다. 한국어 UI와 밝은 테마·다크 모드를 제공합니다.

## 주요 기능

- **러닝 기록**: GPS 거리, 운동 시간, 현재·평균 페이스, 휴대폰 걸음 센서 기반 케이던스. 일시정지·재개·종료, 자동 일시정지와 중단된 운동 복구를 지원합니다.
- **나만의 코스**: 카카오 지도에 지점을 찍고 이동·삽입·삭제하여 코스를 만듭니다. 코스를 따라 달리며 회전 안내와 경로 이탈 알림을 받을 수 있습니다.
- **구간별 페이스 계획**: 거리·시간 구간과 반복 계획, 코스 지점별 목표 페이스를 설정합니다. 코스만, 페이스만, 코스와 페이스를 함께 선택할 수 있습니다.
- **음성·경보·메트로놈**: 목표 페이스 이탈 음성, 빠름·느림 경보, 거리별·시간별 현재 페이스 안내와 목표 케이던스 메트로놈을 각각 설정하고 미리 들을 수 있습니다. 즉시 경보와 안정 확인 방식 중 선택할 수 있습니다. 안내 중 다른 음악에 음량 낮춤 또는 일시정지를 요청하도록 선택할 수 있습니다.
- **기록 분석**: 기록 지도, 1km·코스 지점별 구간 페이스, 페이스·케이던스·GPS 고도 그래프, 주간·월간 거리와 기록 목록을 확인합니다. 목표 달성 운동은 목표까지와 전체 기록을 전환해 볼 수 있습니다.
- **파일 교환과 심박수**: 코스 GPX·JSON 가져오기와 내보내기, 운동 GPX·심박수를 포함한 운동 JSON 내보내기를 지원합니다. 운동 후 Health Connect에 제공된 삼성 헬스 심박수를 가져올 수 있습니다.

## 사용하는 흐름

1. **코스 · 페이스**에서 코스를 만들거나 가져오고, 필요한 페이스 계획을 준비합니다.
2. **달리기**에서 코스·계획·목표를 선택한 뒤 시작합니다. 선택 없이 자유 달리기도 가능합니다.
3. 운동 중 지도와 측정값을 확인하고 일시정지·재개합니다. 목표에 도달해도 기록은 계속되며, **종료**를 눌러 전체 기록을 저장합니다.
4. **기록**에서 요약·구간·그래프·심박수를 확인하거나 파일로 내보냅니다.

위치 상태와 음성 미리듣기는 **설정**에서 확인할 수 있습니다. 운동 시작에는 정확한 위치 권한과 휴대폰 위치 기능이 필요하며, 걸음 센서 기반 케이던스에는 신체 활동 권한이 필요합니다. 화면이 꺼진 동안에는 위치 foreground service와 운동 알림을 사용합니다. 시스템이 운동 프로세스를 종료하면 저장된 기록을 복구한 뒤 사용자가 재개하거나 종료합니다.

## 데이터와 현재 제약

- 운동·코스·계획·가져온 심박수는 로컬에 저장합니다. 지도 표시에는 카카오 서비스와 인터넷 연결을 사용합니다.
- GPS 거리와 페이스는 수신 품질에 영향을 받으며, 케이던스는 휴대폰 걸음 센서에서 추정합니다. GPS 고도와 칼로리도 추정값입니다.
- 코스 길이는 지점 사이의 직선 연결을 기준으로 계산합니다. 실제 보행 경로 자동 탐색과 경로 이탈 후 재탐색은 지원하지 않습니다.
- 시간 구간의 거리는 목표 페이스로 계산한 예상값입니다. 시간 구간이 섞인 계획의 완료를 거리 목표 달성과 동일하게 처리하지 않습니다.
- 심박수는 운동 후 가져오는 방식입니다. Fit3 등 기기의 모든 샘플이 삼성 헬스를 거쳐 Health Connect에 제공된다고 보장하지 않으며, 실시간 워치·BLE 심박수는 지원하지 않습니다.
- GPX는 경로 교환 형식이며 전체 앱 백업이 아닙니다. 운동 JSON에는 전체 운동과 심박수를 내보낼 수 있지만 운동 JSON 재가져오기와 전체 백업·복원 UI는 아직 없습니다. 앱 삭제 시 로컬 데이터도 삭제됩니다.
- 트레드밀, 오프라인 지도, 온라인 코스 검색·공유는 현재 지원하지 않습니다.

## 실행과 검증

Android Studio에서 저장소를 열고 `kakaoDebug`를 선택하여 휴대폰에서 실행합니다. 카카오 네이티브앱 키와 해당 서명 키의 해시 등록이 필요합니다. 자세한 환경 설정, 지도 없는 `previewDebug`와 검사 명령은 [빌드·실행 안내](docs/BUILDING.md)에 있습니다.

[Android build workflow](.github/workflows/android.yml)는 core 테스트, 카카오·preview의 debug 및 simulation 빌드·lint, simulation 단위 테스트를 실행하도록 구성되어 있습니다. 실행 결과는 [GitHub Actions](https://github.com/delvering17/runkeep/actions)에서 확인할 수 있습니다. 자동 검사는 실제 기기의 지도 인증·야외 GPS·음성 출력·Health Connect 동기화를 보장하지 않습니다.

## 기술 구성

| 영역 | 구성 |
| --- | --- |
| 앱·UI | Kotlin, Jetpack Compose, Material 3 |
| 기록 저장 | Room / SQLite |
| 지도·위치 | 카카오 Android 지도 SDK, Google Play Fused Location |
| 운동 안내 | Android TTS, 오디오 경보·메트로놈 |
| 심박수 가져오기 | Health Connect |
| 핵심 로직 | Android에 의존하지 않는 `core` 모듈, JUnit 5 테스트 |

`app`은 화면·서비스·센서·저장을 담당하고, `core`는 거리·페이스·자동 일시정지·코스 진행·구간 통계를 담당합니다. JDK 25로 개발·검사하며 Android 앱과 core의 JVM 타깃은 21입니다.
